# R1.1 H5 兼容性与回归测试规范

## 目标

初见·FRESH 的根页面统一采用“一个视口容器、一个内容滚动区、一个稳定底部栏”。禁止通过 JavaScript 反复测量窗口高度或切换页面时重新挂载底部栏，以避免页面抖动和折叠屏适配回归。

## 设备矩阵

| 场景 | 自动化视口 | 重点检查 |
| --- | --- | --- |
| 小屏手机 | 320 × 568 | 内容可滚动，主操作可到达 |
| 常见安卓 | 360 × 800 | 首屏布局与底栏稳定 |
| 华为 Mate X7 外屏 | 360 × 815 | 首页指引入口首屏可见 |
| 常见 iPhone | 390 × 844 | 安全区和底栏位置 |
| 大屏手机 | 430 × 932 | 卡片比例与留白 |
| 华为 Mate X7 内屏 | 737 × 805 | 展开态布局及横向溢出 |
| 平板 | 768 × 1024 | 居中容器和滚动区域 |
| 桌面浏览器 | 1366 × 768 | H5 容器完整、无横向溢出 |

自动化视口用于覆盖 CSS 断点和交互稳定性，不能完全模拟 HarmonyOS 浏览器外壳。打 Tag 前仍需在真实 Mate X7 上完成一次外屏、内屏和展开/折叠后的人工冒烟。

## 执行规则

- 日常 Issue：只跑本次修改及直接关联的 Node/Playwright 用例，不执行兼容性全量回归。
- 按需全量：出现共享布局、底部栏、视口高度、滚动或安全区修改时执行。
- 打 Tag / 正式发布前：必须执行 R1.1 全量回归，并完成真实 Mate X7 冒烟。

## 命令

```bash
cd frontend
npm run test:responsive
npm run test:release-regression
```

`test:responsive` 只执行设备矩阵兼容性验证；`test:release-regression` 执行 Lint、现有自动化、正式静态构建及设备矩阵，是打 Tag 前的统一入口。

## 验收口径

- 页面无横向溢出，长内容只在内容区滚动。
- 底部栏不遮挡内容，五个根页面切换时位置和高度一致。
- 首页“查看/获取今日能量指引”在常见设备首屏可见；极小屏允许滚动后到达。
- 适配不得改变业务路由、接口调用、用户数据或底栏功能。
- 安全区使用 `env(safe-area-inset-bottom)`，视口高度优先使用 `100dvh` 并保留 `100vh` 回退。
