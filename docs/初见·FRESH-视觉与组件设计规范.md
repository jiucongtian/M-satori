# 初见·FRESH 视觉与组件设计规范

状态：已固化

规范版本：1.0（2026-08-22）

固化结论：作为初见·FRESH 项目级视觉基线，自 R1.0 起执行；后续 Release、H5 原型与 POC 均应引用本文件，不另行复制分叉。

适用范围：H5 原型、R1.0 及后续 Release 前端、测试环境与正式环境

配套规范：《R1.0-字体与排版规范.md》；字体、字号和字重以该规范为准，本文件不重复定义。

## 一、规范目标

1. 让原型、开发、测试使用同一套视觉语言，避免同类组件在不同页面出现颜色、大小、圆角和交互差异。
2. 延续“初见·FRESH”的疗愈感、生命感、东方含蓄感与现代可用性。
3. 让视觉规则可以转化为设计令牌、公共组件和自动化测试，而不是只停留在效果图中。
4. 新页面优先组合既有组件；确需新增样式时，先扩充规范，再进入原型和研发。

## 二、设计原则

### 2.1 温润而清晰

- 大面积使用暖米白与低饱和绿色，避免纯白、纯黑和高饱和色形成刺激。
- 疗愈感不等于低可读性；正文、按钮和关键状态必须清楚可辨。
- 金色用于“指引、生命、收获、重点动作”，不可大面积铺底。

### 2.2 留白承载呼吸感

- 页面不依赖线框堆叠层级，优先通过留白、背景层次和字号区分信息。
- 一个视觉区域只承载一个主要任务；同屏主要按钮原则上不超过一个。
- 装饰动画不得遮挡文字、按钮和卡牌，也不得改变页面布局。

### 2.3 语义一致

- 相同颜色在全系统表达相同含义。
- 相同操作使用相同组件：返回、确认、继续、删除、联系我们等不得各页重新设计。
- 组件状态必须完整覆盖默认、按下、聚焦、加载、禁用、成功和失败。

### 2.4 移动端优先

- 以 390 × 844 作为设计基准，同时兼容 320px 至 520px 宽度。
- 所有可点击区域最小 44 × 44px；视觉图形可以更小，热区不能更小。
- 必须适配 iPhone 安全区、Safari、微信内置浏览器和主流安卓浏览器。

## 三、设计令牌体系

设计令牌分为三层：基础令牌只描述颜色本身，语义令牌描述用途，组件令牌描述具体组件。业务页面不得绕过语义层直接新增颜色。

| 令牌 | 色值 | 用途 |
| --- | --- | --- |
| `--fresh-green-900` | `#283B34` | 深色标题、关键正文 |
| `--fresh-green-700` | `#456B5B` | 品牌主色、主要按钮、选中状态 |
| `--fresh-green-500` | `#718178` | 次级文字、辅助图标 |
| `--fresh-green-100` | `#D8DDD7` | 外部背景、浅边界与氛围层 |
| `--fresh-cream-050` | `#FAF8F0` | 高亮表面、输入框背景 |
| `--fresh-cream-100` | `#F6F2E8` | 产品主背景 |
| `--fresh-cream-200` | `#F1EEDD` | 次级背景、分层表面 |
| `--fresh-gold-500` | `#D7A35A` | 指引、生命、收获与关键点缀 |
| `--fresh-gold-700` | `#A27A43` | 金色文字、英文眉题 |
| `--fresh-white` | `#FFFFFF` | 浮层、高对比文字 |

说明：以上颜色从 R1.0 已验证页面提取。后续允许微调，但必须通过规范版本变更，不得由单页自行修改。

### 3.2 语义色

| 令牌 | 建议映射 | 使用规则 |
| --- | --- | --- |
| `--color-bg-page` | `--fresh-cream-100` | 页面主体背景 |
| `--color-bg-stage` | `--fresh-green-100` | 桌面预览或页面外部背景 |
| `--color-surface-primary` | `rgba(255,255,255,.62)` | 内容卡、协议正文、弹窗 |
| `--color-surface-secondary` | `rgba(255,255,255,.46)` | 次级列表和轻量模块 |
| `--color-brand-primary` | `--fresh-green-700` | 主按钮、选中、品牌动作 |
| `--color-brand-accent` | `--fresh-gold-500` | 强调、指引和生命节点 |
| `--color-text-primary` | `--fresh-green-900` | 标题、正文 |
| `--color-text-secondary` | `--fresh-green-500` | 辅助说明 |
| `--color-text-on-dark` | `#FFFDF6` | 深色卡片上的文字 |
| `--color-border-subtle` | `rgba(69,107,91,.12)` | 普通边界 |
| `--color-border-strong` | `rgba(69,107,91,.28)` | 聚焦、选中、强调边界 |
| `--color-state-success` | `#557B65` | 完成、成功 |
| `--color-state-warning` | `#B3834D` | 提醒、余额不足、待处理 |
| `--color-state-error` | `#A85D50` | 失败、危险、删除 |
| `--color-state-disabled` | `#AAB5AF` | 禁用文字及控件 |

状态色只用于状态反馈，不参与大面积品牌装饰。错误信息应同时提供文字或图标，不能只依赖颜色。

### 3.3 间距

采用 4px 基础网格。

| 令牌 | 数值 | 主要用途 |
| --- | ---: | --- |
| `--space-1` | 4px | 图标与短文字 |
| `--space-2` | 8px | 紧凑组件内部间距 |
| `--space-3` | 12px | 表单、列表内部间距 |
| `--space-4` | 16px | 常规组件间距 |
| `--space-5` | 20px | 卡片内边距 |
| `--space-6` | 24px | 内容分组间距 |
| `--space-8` | 32px | 页面章节间距 |
| `--space-10` | 40px | 主内容段落间距 |
| `--space-12` | 48px | 首屏大留白 |

- 手机页面左右安全边距默认 24px；320px 窄屏可缩至 18px。
- 同级组件只使用令牌间距，不新增 13px、17px 等零散数值。
- 视觉微调允许使用 1px/2px，但不能作为布局主间距。

### 3.4 圆角

| 令牌 | 数值 | 用途 |
| --- | ---: | --- |
| `--radius-xs` | 8px | 小标签、轻量状态 |
| `--radius-sm` | 12px | 小按钮、小输入组件 |
| `--radius-md` | 16px | 常规输入框、列表项 |
| `--radius-lg` | 20px | 内容卡片 |
| `--radius-xl` | 24px | 重点卡片、弹窗 |
| `--radius-shell` | 34px | 手机原型外壳 |
| `--radius-pill` | 999px | 胶囊按钮、状态标签 |

同一组件在不同页面必须使用同一个圆角令牌。矩形操作按钮默认不使用完全直角。

### 3.5 阴影与层级

| 令牌 | 建议值 | 用途 |
| --- | --- | --- |
| `--shadow-soft` | `0 8px 20px rgba(40,59,52,.08)` | 输入框、轻卡片 |
| `--shadow-card` | `0 16px 36px rgba(40,59,52,.12)` | 重点内容卡 |
| `--shadow-floating` | `0 22px 60px rgba(40,59,52,.16)` | 弹窗、浮层 |
| `--shadow-focus` | `0 0 0 3px rgba(215,163,90,.22)` | 键盘聚焦与关键选择 |

- 阴影用于表达层级，不用于装饰堆叠。
- 同一卡片不得同时使用重阴影、粗边框和高饱和背景。
- 毛玻璃只允许用于明确登记的氛围型卡片；普通按钮不得使用 `backdrop-filter`。

### 3.6 动效

| 令牌 | 数值 | 用途 |
| --- | ---: | --- |
| `--motion-fast` | 120ms | 按钮按下、图标反馈 |
| `--motion-normal` | 240ms | 弹层、状态切换 |
| `--motion-slow` | 600ms | 页面内容渐入 |
| `--motion-life` | 3500ms–8000ms | 种子、枝叶、呼吸动效 |

- 功能动效采用 `ease-out`；生命动效采用柔和 `ease-in-out`。
- 底部导航切换不得触发整页闪白或重新入场。
- 遵循 `prefers-reduced-motion`；用户减少动态效果时停用位移、旋转和持续循环。

## 四、基础组件规范

### 4.1 主要按钮 Primary Button

- 用途：完成当前页面唯一的核心动作，如“登录/注册”“继续”“确认并创建档案”。
- 高度：52px；紧凑场景不得低于 48px。
- 宽度：移动端默认通栏；左右与页面内容对齐。
- 背景：`--color-brand-primary`；文字使用 `--color-text-on-dark`。
- 圆角：`--radius-md`；大首屏按钮可用 `--radius-lg`。
- 字体：`--type-body-strong`，字重 600。
- 箭头与文字间距：8px；箭头不得独立漂移。
- 同屏最多一个 Primary Button。

状态：

| 状态 | 表现 |
| --- | --- |
| 默认 | 主绿色背景，白色文字 |
| 按下 | 整体透明度 88%，轻微缩放至 99% |
| 聚焦 | 保留主色并增加 `--shadow-focus` |
| 加载 | 保持原尺寸，文字替换为状态文案并显示轻量进度 |
| 禁用 | 灰绿色背景，不可点击；必须说明原因 |

### 4.2 次要按钮 Secondary Button

- 用途：返回上一步、稍后处理、重新填写等次级动作。
- 高度：48px；边框使用 `--color-border-strong`。
- 背景为浅色表面，文字使用主绿色。
- 不得通过高饱和颜色与主要按钮竞争。

### 4.3 文字按钮 Text Action

- 用途：查看详情、获取今日能量指引、联系我们等轻操作。
- 视觉只显示文字与可选箭头，不显示矩形背景。
- 实际点击热区最小 44 × 44px。
- 必须显式清除背景、边框、阴影、滤镜和毛玻璃效果。
- 危险文字按钮使用错误色，并必须配合确认机制。

### 4.4 返回按钮 Back Button

- 点击热区：44 × 44px。
- 视觉容器：44 × 44px，圆角 15px；普通内容页使用浅色表面和细边框。
- 图标：统一使用左箭头，视觉尺寸 20–22px，不混用字符、图片和多套图标。
- 位置：页面左上角安全区内，与标题栏垂直居中。
- 返回目标必须明确，不得只依赖不可预测的浏览器历史。
- 首个强制流程页面、生成完成页等产品定义不可返回的页面，不展示占位按钮。

### 4.5 图标按钮

- 适用于关闭、更多、分享等动作。
- 热区最小 44 × 44px；图标视觉尺寸 18–22px。
- 必须提供可访问名称，如 `aria-label="关闭"`。
- 同一动作全系统使用同一图标，不使用含义模糊的装饰符号。

### 4.6 输入框

- 高度：56px；多行输入按内容扩展。
- 圆角：`--radius-md`；背景使用 `--color-surface-primary`。
- 默认边框：`--color-border-subtle`；聚焦边框使用主绿色并增加轻焦点环。
- 输入文字使用 `--type-body`；标签使用 `--type-secondary`。
- 占位文字不能代替字段标签。
- 错误信息位于字段下方，说明问题与修复方法；不得只将边框变红。
- 手机号、验证码、日期和数字字段必须使用正确的移动键盘类型。

### 4.7 开关 Switch

- 关闭：灰绿色轨道；开启：主绿色轨道；圆形滑块使用白色。
- 整行均可点击，热区高度不低于 44px。
- 未开放能力可以展示关闭状态，但点击后应说明当前版本状态，不伪装为可用。
- 开关控制的附加字段仅在开启后出现，避免提前增加认知负担。

### 4.8 标签与状态 Badge

- 只用于短状态，如“生成中”“已完成”“研发中”。
- 高度 24–28px，圆角使用 `--radius-pill`。
- 一张卡片最多展示两个状态标签。
- Release 和页面编号属于测试信息，正式环境必须隐藏。

## 五、容器与业务组件

### 5.1 普通内容卡

- 背景：`--color-surface-primary`。
- 圆角：`--radius-lg`。
- 内边距：20px；复杂报告卡可用 24px。
- 边框与阴影二选一为主，不同时强化。

### 5.2 深绿色疗愈卡

- 用途：首页能量、关键报告摘要、智慧种子等重点内容。
- 使用低饱和绿渐变和轻透明层次，不使用单一深色实心块。
- 卡内主文字使用暖白，辅助信息控制在 70%–80% 不透明度。
- 金色只用于能量、指引、种子和主要动作。
- 动画层永远位于内容层下方，完整可见且不裁切关键枝叶。

### 5.3 生命智慧卡牌

- 卡牌图片保持原始比例，不裁切牌面文字与编号。
- “时空关系卡、事业关系卡、家庭关系卡、自我关系卡”展示在图片下方，不叠加在牌面上。
- 干支已经存在于卡牌图片时，不重复显示。
- 加载失败必须提供同尺寸占位，避免页面跳动。
- 全系统统一使用卡牌资产映射组件，禁止页面自行拼接路径。

### 5.4 智慧种子组件

- 余额组件全系统读取同一真实账户数据源。
- 种子图形、数值和单位的顺序保持统一。
- 消耗前明确所需数量；消耗后刷新真实余额。
- 余额不足时提供清晰的客服帮助入口，不显示无后续动作的死提示。

### 5.5 报告内容块

- 顶部先展示报告身份、日期和核心摘要，再进入章节内容。
- 长正文遵循字体规范，正文不小于 14px、行高不低于 1.75。
- 章节间距至少 32px；正文内部段落间距至少 16px。
- AI 生成内容与确定性计算信息必须分别标注边界。

## 六、导航、弹层与反馈

### 6.1 五项底部导航

- 固定顺序：今日、问事、关系、成长、我的。
- 五等分布局，切换页面时尺寸、位置和高度不变化。
- 图标与文字垂直排列；选中态使用主绿色与金色点缀。
- 底部适配 `env(safe-area-inset-bottom)`。
- 导航切换使用稳定的单页状态，不产生整页刷新和闪屏。

### 6.2 弹窗 Dialog

- 用于删除、退出、不可逆操作和必须打断流程的选择。
- 宽度不超过页面可用宽度减 40px；圆角使用 `--radius-xl`。
- 标题说明发生什么，正文说明影响，按钮说明动作。
- 危险操作按钮使用错误色；取消操作使用次要按钮。
- 普通成功提示不得滥用弹窗。

### 6.3 Toast

- 用于保存成功、复制成功、轻量失败等短反馈。
- 显示 2–3 秒；用户需要采取行动的错误不得自动消失。
- 同一时间只展示一个 Toast。

### 6.4 空、加载与失败状态

- 空状态：说明当前没有什么，并提供一个明确下一步。
- 加载状态：保留页面骨架，避免整体跳动；超过 2 秒显示说明文案。
- 失败状态：保留用户已填写内容，提供重试和安全返回路径。
- 网络失败不得重复扣除智慧种子或重复生成任务。

## 七、页面布局规范

- 页面基准宽度 390px；桌面环境最大展示宽度由容器控制，不将手机内容横向拉伸。
- 页面顶部、正文和底部操作使用统一内容边线。
- 固定底部导航存在时，滚动内容必须预留安全空间，不得遮挡最后一个操作。
- 页面主按钮靠底时必须跟随安全区；内容不足时贴近底部，内容超长时随页面滚动。
- 页面禁止横向滚动；长英文、请求编号和昵称必须支持安全换行。
- 页面编号仅测试构建显示，正式构建由环境变量统一关闭。

## 八、原型与研发协作规则

### 8.1 命名一致

原型、代码和测试统一使用以下层级：

```text
设计令牌 Token
  └── 基础组件 Primitive
        └── 业务组件 Pattern
              └── 页面 Page
```

示例：`color-brand-primary → PrimaryButton → SeedConsumeAction → DAILY-01`。

### 8.2 原型要求

- 页面必须标注 Release 和页面编号；正式用户界面不显示编号。
- 新页面应注明复用的组件名称，避免只通过截图沟通。
- 组件新增或变体必须同步更新本规范。
- 原型调整涉及公共组件时，需要列出受影响页面，不得只修改当前页面。

### 8.3 开发要求

- CSS/组件只使用已批准令牌，不得新增临时十六进制颜色和零散尺寸。
- 公共组件不得被页面选择器无边界覆盖。
- 每个组件必须包含交互状态和移动端兼容处理。
- 业务数据、显示文案和视觉状态分离，禁止用颜色推断业务状态。

### 8.4 测试要求

- 日常开发运行功能测试；视觉规范自动检查在正式上线前作为发布门禁统一执行。
- 重点检查 320px、390px、430px 和桌面容器宽度。
- 正式发布前至少覆盖 iPhone Safari、微信内置浏览器和一款安卓 Chromium 浏览器。
- 视觉回归重点：按钮背景、返回键、底部导航、卡牌比例、安全区、长昵称、长报告和加载失败。

## 九、禁止事项

1. 禁止为单个页面临时创造新的品牌色。
2. 禁止同一操作在不同页面使用不同按钮形态。
3. 禁止普通按钮使用毛玻璃滤镜。
4. 禁止小于 44 × 44px 的点击热区。
5. 禁止用纯颜色作为唯一状态提示。
6. 禁止底部导航随页面切换改变位置、尺寸或顺序。
7. 禁止装饰动画遮挡信息或影响页面布局。
8. 禁止在正式环境展示页面编号、Release 标记和内部状态码。
9. 禁止页面直接引用未经审核的第三方组件默认样式。
10. 禁止原型、代码和规范长期存在三个不同版本。

## 十、工程化落地建议

规范确认后按三步落地：

1. 在 `frontend/app/globals.css` 建立完整的颜色、间距、圆角、阴影和动效令牌，并保留旧令牌的兼容映射。
2. 抽取 `Button`、`IconButton`、`BackButton`、`Input`、`Switch`、`Card`、`Badge`、`Dialog`、`Toast`、`MainNav` 等公共组件。
3. 先迁移登录注册、HOME-01、每日指引和“我的”四组 R1.0 页面；视觉验收通过后，再作为 R1.1 新页面的强制基线。

迁移原则是保持当前已确认的视觉效果，优先消除重复和不一致，不在同一轮进行大规模风格改版。

## 十一、版本治理

- 本规范作为项目级规范，不限定于 R1.0；文件名不带具体 Release。
- 小幅补充升级修订号，如 1.0 → 1.1；改变品牌主色、圆角体系或组件交互属于大版本变更。
- 每次变更必须记录：变更原因、影响组件、影响页面、实施 Release 和验证结果。
- 其他项目或 POC 应通过引用本文件或同步令牌包复用，不复制后自行分叉。
