# R1.0 本人称呼持久化候选契约

> 状态：待后端支持。关联 GitHub Issue #2。

## 问题

本人生命智慧档案当前固定返回“我的生命智慧档案”，建档 preview/confirm 也不接收用户在 PROFILE-02 填写的称呼，导致跨会话、跨设备重新登录后无法恢复如“Fred”这样的用户称呼。

## 候选接口

```http
PATCH /api/v1/me/life-profile
Content-Type: application/json
Idempotency-Key: <uuid>

{
  "displayName": "Fred"
}
```

成功响应继续复用 `LifeProfileEnvelope`，其中：

- `subjectType` 必须为 `SELF`；
- `displayName` 为已持久化称呼；
- 长度 1—16 个用户可见字符，去除首尾空白；
- 不修改出生信息、档案 revision 或既有报告依据；
- `GET /me/life-profile` 与 `GET /me/home-overview` 必须返回同一 `displayName`。

## 前端接入时机

在本人档案首次确认成功后提交称呼；若称呼写入失败，保留档案确认结果并提示重试，不重复计算档案。后续编辑称呼复用同一接口。

## 验收

- 首次填写 Fred 并确认建档后，重新登录、刷新和跨设备登录均返回 Fred。
- 不再以固定档案标题代替用户称呼。
- 重复请求幂等，不改变档案 revision。
- 补充接口契约、持久化、权限与前端恢复测试。
