## 0. 重新开始工作时先做什么

无论距离上次研发过了多久，先按以下顺序恢复上下文：

1. 阅读本文的“当前快照”“立即下一步”和“待决策事项”。
2. 在仓库根目录执行下面的只读检查，确认文档没有过期：

   ```bash
   git status --short --branch
   git branch -vv --all
   git tag --list --sort=-creatordate
   git log --oneline --decorate --all -n 20
   find backend -maxdepth 3 -type f -print
   ```

3. 确认本次任务属于 R1.0 还是 R1.1，再选择工作分支；不要以当前端口号代替版本判断。
4. 检查未跟踪和未提交文件，不要在切分支时覆盖其他人或上一次留下的工作。
5. 开始实现前，将本次的目标、分支、负责人和验收方式写入文末“交接记录”。

## 2. 状态口径

交接、Issue、OpenAPI 和联调表统一使用以下口径：

| 状态 | 含义 | 允许对外宣称“可用” |
| --- | --- | --- |
| `NOT_STARTED` | 无可运行实现 | 否 |
| `CONTRACT_DEFINED` | 讨论稿已定义，本轮未验证后端 | 否 |
| `CONTRACT_PROPOSED` | 前端候选契约，待后端评审 | 否 |
| `CONTRACT_FROZEN` | 双方已评审并纳入版本化 OpenAPI | 否 |
| `IMPLEMENTED` | 后端已实现且本地测试通过 | 否 |
| `DEPLOYED` | 已部署到可访问测试环境 | 仅可称“可联调” |
| `FRONTEND_ADAPTER_READY` | 前端有类型或调用适配器 | 否 |
| `MOCK_UI` | 页面由本地状态/演示数据驱动 | 否 |
| `INTEGRATED` | 前端已调用测试环境真实 API | 只表示已接入 |
| `VERIFIED` | 契约、集成、E2E 和关键异常路径通过 | 是 |

当前整体仅处于 `NOT_STARTED + CONTRACT_DEFINED / CONTRACT_PROPOSED + MOCK_UI`，没有任何能力可标记为 `IMPLEMENTED`、`INTEGRATED` 或 `VERIFIED`。

## 4. R1.1 产品边界和候选契约

R1.1 包含 R1.0 全部九项，并开放“抽卡问事”：问题与分类、1—5 张卡、系统随机抽取、按张数消耗智慧种子、翻牌、异步报告、失败恢复、历史、反馈和分享。

| `POST` | `/card-readings/{readingId}/feedback` | 提交反馈 | `CONTRACT_PROPOSED` | `NOT_STARTED` | `FRONTEND_ADAPTER_READY` + `MOCK_UI` | 幂等/防重，绑定报告版本 |

候选核心字段：

- 抽卡：`question`、`category`、`cardCount(1..5)`、`deckCode=RELATIONSHIP_WISDOM_DEFAULT`、`drawMethod=SYSTEM_RANDOM`、`positionLabels`；
- 生成：`drawId`、`audience=CONSUMER`、`settlement.currency=WISDOM_SEED`、`settlement.amount`；
- 反馈：`CLEARER | INSPIRED | NEEDS_TIME | NOT_HELPFUL`；
- 报告五段：`OPENING | SELF | CARDS | ACTION | CLOSING`。

需在契约评审时确认抽卡报告是否复用 `/generation-tasks/{taskId}` 和 SSE。如复用，必须共用任务状态、错误码、心跳、断线重连和重试规则，不建第二套任务系统。

## 5. 不可违背的跨端约束

### 5.1 智慧种子结算

每日指引和抽卡问事必须共用一套账务模型：

1. 接受任务前校验可用余额；
2. 接受后预占，成功可交付后核销；
3. 失败、取消或不可交付时释放/退回；
4. 同一 `Idempotency-Key` 重放不得重复扣费；
5. 账户余额与流水在同一事务边界内写入；
6. 流水保存业务类型、资源 ID、幂等键和变更后余额；
7. 最终余额以后端响应为准，前端不自行推算。

结算状态统一为 `RESERVED | CONSUMED | RELEASED | REFUNDED`；流水类型为 `GRANT | RESERVE | CONSUME | RELEASE | REFUND | ADJUSTMENT`。所有内容生成只用智慧种子结算，不直接现金支付。

### 5.2 安全、数据和任务

- 所有私有资源都要在服务端校验当前用户和资源归属。
- 生成输入、模型/提示版本、生成结果和结算记录必须可追溯。
- 抽卡结果由服务端产生并冻结，不接受 H5 指定具体牌。
- 异步任务必须有明确终态，查询和 SSE 返回的状态语义必须一致。
- Token 过期、限流、幂等重放、余额不足、生成失败和不可重试都要有稳定错误码。
