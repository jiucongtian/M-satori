# R1.1 · 抽卡问事验收用例

覆盖原型 READ-01—25 的用户主闭环。当前已落地的路由基础（READ-01、READ-02、历史入口）先纳入自动化；其余用例随对应功能实现转为自动化断言。

| 编号 | 场景 | 核心预期 | 状态 |
| --- | --- | --- | --- |
| R11-READ-001 | 进入问事 | 已登录用户可从底部“问事”进入 `/readings`；首页、发起页、历史页均受登录保护。 | 已自动化 |
| R11-READ-002 | 开始提问 | “开始一次新的问事”和推荐问题均进入 `/readings/new`；问题少于 6 字不能继续；最多 120 字。 | 已自动化 |
| R11-READ-003 | 问题边界 | 用户可选择问题方向；涉及第三方窥探、绝对化预测等问题，进入澄清或安全提示，而不是直接生成。 | 待自动化 |
| R11-READ-004 | 牌阵与方式 | 默认牌阵、默认随机抽牌规则清晰可见；确认后，问题、牌阵和抽牌方式冻结。 | 待自动化 |
| R11-READ-005 | 权益确认 | 创建生成任务前展示本次消耗、当前可用和使用后可用；有效报告形成后才核销。 | 待自动化 |
| R11-READ-006 | 权益不足 | 权益不足时保留问题与配置；可前往合规购买路径、改为可用方案或稍后继续，不能重复扣除。 | 待自动化 |
| R11-READ-007 | 抽牌与确认 | 牌面揭示后，用户确认的卡牌与位置固定；失败重试不得重新抽牌。 | 待自动化 |
| R11-READ-008 | 生成与恢复 | 生成中可离开；网络中断、生成失败、重试和超时恢复均保留原问题与原卡牌，且不重复扣费。 | 待自动化 |
| R11-READ-009 | 报告交付 | 完成后展示报告、卡牌依据和生成时间；报告保存到问事历史及成长报告库。 | 待自动化 |
| R11-READ-010 | 历史与续读 | 用户可按类型查看历史、打开已完成报告，并从生成中或失败记录继续处理。 | 待自动化 |
| R11-READ-011 | 分享隐私 | 默认不公开原始问题；用户可选择分享范围，生成失败或网络异常有可恢复反馈。 | 待自动化 |

## 实施原则

1. 每一个新路由、状态机或后端契约，至少绑定一个 `R11-READ-*` 用例。
2. 用例先写清“何时扣权益、何时恢复、如何幂等”，再实现前后端。
3. 页面文案或视觉调整不改变业务预期时，只需更新视觉基线，不重写业务用例。
