# R1.1 测试基线

本目录是 R1.1 的业务验收基线。每条用例以 `R11-` 编号管理，并与 `frontend/tests/r1.1/` 内同编号的自动化检查对应。

## 两种使用方式

1. **研发参考**：开发或调整功能前，先查看对应业务用例的前置条件、操作和预期结果；功能范围变更时，先更新用例，再更新实现。
2. **版本验证**：日常仅执行本次改动对应的用例。用户明确说“打 Tag”或“全量回归”时，执行完整回归基线。

## 目录约定

- `R1.1-全量功能-验收矩阵.md`：以最新 H5 原型为唯一范围来源的全量功能矩阵。
- `R1.1-抽卡问事-验收用例.md`：问事主闭环的细化业务验收用例。
- `../../../../frontend/tests/r1.1/`：可执行的自动化测试与全量回归执行器。

## 执行约定

在 `frontend` 目录执行：

```bash
# 仅验证 R1.1 问事已自动化的关键路径
node --test tests/r1.1/*.test.mjs

# R1.1 全量回归（仅在打 Tag 或明确要求全量回归时执行）
node tests/r1.1/run-full-regression.mjs
```

全量回归会依次运行：既有单元/契约测试、R1.1 测试、代码规范检查和静态构建；任一环节失败都会保留失败项并以非零状态结束。

> 当前 `release/r1.1` 尚未合入 R1.1 产品前端和后端源码。依赖产品源码的前端用例会明确显示为“跳过”，不计入通过率；P0 后端契约 Mock 检查可运行，但不等同于真实后端集成测试。

## 状态标识

- `已自动化`：已有可执行检查。
- `待自动化`：需求已明确，但实现或测试夹具尚未准备完成。
- `待确认`：原型或产品规则仍可能变化，不应提前固化为强制断言。
