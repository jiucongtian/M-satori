# 五福荟 R1.1：版本范围与交付总览

## 1. 产品目标

将现有“初见”体验升级为“五福荟”，让用户通过小岁的讲述理解报告与自己的关系；让运营能够调整页面编号、抽卡模式和导航；让主系统注册和外部引流用户都在进入首页前体验一次每日指引。

本版保留既有账号、生命智慧档案、智慧种子和报告承接关系。具体报告的五福结构由用户后续提供的模板确定，不能只将标题替换为“五福”就视为完成内容升级。

## 3. 版本边界

R1.1 包含品牌替换、报告表达与结构升级、小岁静态形象及简短介绍、三项运营配置、每日指引前置、POC 同步。

小岁语音属于第二阶段，本次不交付，目标版本尚未指定，不能默认归入 R1.2。五福关系匹配的新建模、卡牌皮肤选择和真太阳时记入 [R1.2 备忘](06-R1.2需求备忘.md)。

本版“报告按五福组织”不等于新增四类关系对象录入，也不自动新增月运、年运等尚未开放的报告产品。适用对象为本版实际交付的全部报告；每种报告必须在模板清单中明确如何体现五福，不要求凭空凑齐五段相同内容。

## 4. 关键用户故事

- 作为初次用户，我希望从进入产品到阅读报告都能识别五福荟，并感受到是小岁在向我讲述。
- 作为注册用户，我希望建档完成后就看到自己的每日指引，不用进入首页后再次寻找和启动。
- 作为收到链接的人，我希望按主系统的同一套注册与档案流程得到自己的报告，之后能继续使用完整产品。
- 作为运营人员，我希望无需改代码就能调整页面编号、抽卡模式和导航，并知道配置何时生效、如何恢复。

## 5. 交付物与依赖

| 交付物 | 要求 |
| --- | --- |
| 版本 PRD | 本目录，需求编号、流程、范围、异常、验收和待决策齐全 |
| 设计与素材 | 五福荟 Logo、小岁正式画像、介绍文案、报告示例、配置页面及流程原型 |
| 内容模板 | 每种报告的输入、五福映射、章节、叙述口吻、示例及版本 |
| 工程交付 | 前后台配置、统一首次体验、内容生成与展示适配、POC 对齐 |
| 验收证据 | 关联 Issue、PR/commit、环境版本、测试结果、内容与产品确认 |

Logo、IP 与报告模板未提供不妨碍完成本 PRD 和流程评审，但会阻塞对应功能的最终设计及验收。不得用临时素材或自行编造的知识规则替代正式确认。

## 6. 成功结果

验收以 [05](05-验收矩阵与待决策事项.md) 为准。上线后观察两类入口的注册完成率、建档完成率、每日指引生成成功率、报告打开率及进入首页转化率。指标目标值需要用现有数据评估后冻结，本文不虚构基线或承诺数值提升。
