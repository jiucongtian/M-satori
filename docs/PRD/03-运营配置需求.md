# 运营配置需求

需求：WFH11-03、WFH11-04、WFH11-05。在现有运营管理后台增加配置能力，不另建一套后台。

## 1. 配置通用规则

用户明确要求三项能力可通过后台控制。以下发布、默认值和异常行为为本 PRD 的设计建议，进入开发前随配置原型冻结。

- 配置区分原型、测试、正式环境，显示当前编辑环境和已生效版本；测试变更不能直接影响正式环境。
- 授权运营可编辑和发布；只读人员只能查看。复用现有角色权限，不因本需求新增一整套组织体系。
- 编辑 → 校验/预览 → 发布 → 查看生效结果；保存草稿不改变线上行为。可恢复上一个有效版本，并记录操作者、时间、原因和前后差异。
- 配置整体原子生效，不能短暂出现菜单一半新一半旧。页面刷新或重新进入对应流程时读取已发布版本；发布结果提示这一生效时机。
- 已有会话、订单、报告与权益不因开关改变而丢失；配置改变的是新入口及新请求是否可用，不是删除历史业务事实。
- 无有效新配置时保留最近有效版本；全新客户端读取失败时提供重试及基础导航，不能根据加载失败误开放受限功能。创建业务任务必须由服务端再次校验。

## 2. 页面编号开关

### 用户故事与字段

作为运营/测试人员，我希望打开页面编号用于沟通定位，也能关闭它以展示正式体验。

| 项目 | 要求 |
| --- | --- |
| 配置字段 | 页面编号显示：开 / 关 |
| 作用范围 | 当前环境、本版交付页面；覆盖原型和测试环境 |
| 初始建议 | 原型、测试开启；正式关闭；以发布时冻结的配置为准 |
| 开启效果 | 展示稳定的页面编号，切换路由时对应更新 |
| 关闭效果 | 不渲染编号，不留下占位空白；仍可通过内部日志定位页面 |

编号是稳定页面标识，不是页面标题或菜单名称。导航改名、排序后编号不变。已有编号复用，不在 PRD 中虚构新的正式页面编号；缺失页面在设计交付时补登记。

编号不得遮挡按钮、弹窗或输入框，不泄露内部接口、凭据等信息。分享图片默认不嵌入调试编号。可交互原型读取同一配置规则；静态导出稿应注明导出时配置，不能宣称可实时受后台控制。

## 3. 抽卡模式开关

### 已确认能力

后台能控制只开放一张、开放一张和两张、或开放多张卡等组合。PRD 使用正式术语“抽卡问事”；用户口述中的“问世”按该业务理解。

### 配置模型建议

| 模式 | 配置 | 说明 |
| --- | --- | --- |
| 单卡 | 启用/停用 | 1 张 |
| 双卡 | 启用/停用 | 2 张 |
| 多卡 | 启用/停用 | 参考 PRD 为 3—5 张；实际开放数量在实施前核对并冻结 |

采用三个可独立勾选的模式，支持 `{单卡}`、`{单卡,双卡}`、`{单卡,双卡,多卡}`。是否允许“仅双卡/仅多卡”等其余组合待确认。草案建议：问事功能仍对外开放时至少启用一种模式，全部关闭应校验阻止发布；如需暂停整个问事业务，单独定义而非隐含在卡数开关里。

### 行为与边界

- 新进入用户仅看到已启用且当前产品实际支持的模式；默认选中第一个可用模式。
- 未支持的模式不能仅通过勾选变成可用；发布前校验对应模板、商品/权益及服务能力。
- 用户已选模式、尚未正式创建任务时若模式关闭，提交时提示重新选择，保留问题文本，不先扣费再拒绝。
- 请求中手工传入停用模式也必须被服务端拒绝；隐藏按钮不构成业务限制。
- 已成功创建的任务继续按创建时规则完成；历史报告仍可查看，不因模式关闭而删除。
- 若存在模式相关在售商品，发布前显示影响并阻止仍售卖无法使用的新商品；历史已购权益的处理方案必须明确，不能默认清零。
- 同一模式的前端选项、服务端允许数量、生成模板及权益核销一致，异常时不产生重复任务和扣减。

## 4. 导航菜单配置

用户明确要求当前“首页、问事、关系、成长、我的”纳入后台配置。可配置字段尚未逐项指定，以下为建议的最小交付范围：名称、显示/隐藏、显示顺序。图标自由上传、任意 URL 跳转或新增未知功能不计入本版默认范围。

| 字段 | 规则 |
| --- | --- |
| 菜单标识 | 固定，不随名称变化，绑定已有功能入口 |
| 展示名称 | 必填，移动端不能遮挡/截断关键识别文字；最大长度在原型评审冻结 |
| 是否显示 | 控制菜单展示；不自动改变业务权限 |
| 顺序 | 已显示菜单顺序唯一、预览与发布结果一致 |
| 目标页面 | 选择已有有效目标，不由运营任意输入外部地址 |

首页和“我的”涉及首次流程落点及账号管理，草案建议保留为必显项，其名称和顺序可配置。其余菜单可隐藏。若业务希望首页/我的也可隐藏，必须先定义替代落点和账号入口，作为待决策事项冻结。

隐藏菜单不等同于下线整个模块：已有合法深链、历史报告入口仍按权限访问；如果需要禁止访问，应使用对应业务规则，不能将视觉隐藏当作访问控制。隐藏当前选中的菜单后，下次刷新落到可用首页，避免空白。重命名不修改路由、报告归属或埋点中的稳定菜单 ID。

## 5. 最小设计交付

运营配置入口、三个配置区、环境和版本提示、预览、校验失败、发布成功、权限不足、加载失败、回退确认；前台显示/隐藏及模式切换的对照原型。具体页面编号在设计登记后回链 Issue。

验收需覆盖运营实际操作到前台效果的完整链路，不能只以数据库中已有配置值或静态原型作为已交付证据。
