# R1.0 视觉与组件一致性审计

审计日期：2026-08-22

审计依据：《初见·FRESH-视觉与组件设计规范》《R1.0-字体与排版规范》

## 本轮结论

R1.0 已具备统一品牌、字体、主导航与卡牌展示基础，但历史页面仍保留较多直接色值、圆角和局部按钮样式。为避免一次性替换造成已验收页面偏移，本轮先建立项目级设计令牌和公共基础组件，并把高频页面头部迁移到统一返回组件。

## 本轮已完成

- 固化项目级视觉与组件规范，后续 Release、H5 原型和 POC 统一引用。
- 建立颜色、间距、圆角、阴影、动效语义令牌，并保留旧变量兼容映射。
- 建立主要按钮、次要按钮、文字按钮、危险按钮、返回按钮和基础表面组件。
- 将每日指引、问事、成长、关系、我的五类公共页面头部迁移到统一返回组件。
- 为公共组件、设计令牌和规范状态增加自动化回归检查。
- 将 R1.0 高频主要按钮、次要按钮、文字操作与返回按钮统一到规范状态。
- 将登录注册、建档和档案编辑中的输入、选择、聚焦及禁用状态统一到规范。
- 将 R1.0 内容卡、深色摘要卡、底部弹层、确认弹窗和五项导航统一到语义令牌。
- 增加减少动态效果适配；业务路由、接口调用、状态机和页面信息结构保持不变。

## 后续迁移优先级

### P1：高频交互组件

- 将登录注册、档案创建、每日指引和“我的”页面的主要按钮迁移到公共按钮。
- 抽取输入框、单选、日期类型切换和真太阳时开关。
- 统一加载、禁用、错误和成功反馈，避免只靠文字或颜色表达状态。

### P2：视觉容器与装饰

- 将卡片、信息面板和弹层逐步迁移到统一圆角、边框和阴影令牌。
- 清理存量页面中的直接色值和重复阴影，但每批都需要截图回归。
- 将生命动画的时长、透明度和层级统一到动效令牌。

## 迁移约束

1. 不允许为了“统一”一次性重写全部样式；每批只处理一类组件。
2. 已验收页面迁移前后必须完成 390px、iPhone Safari/微信浏览器截图对比。
3. 新页面不得再直接创建新的主色、按钮、返回键或输入框样式。
4. 任何会改变业务路径、页面信息结构或原型视觉的调整，必须单独确认，不与组件迁移混在一次提交中。
