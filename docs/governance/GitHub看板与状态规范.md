# GitHub 看板与状态规范

## Project 字段

| 字段 | 类型/值 |
| --- | --- |
| Status | 待梳理、待开发、开发中、待测试、待验证、已关闭 |
| Release | R1.0、R1.1、Backlog |
| Type | Bug、Feature、优化、技术治理 |
| Priority | P0、P1、P2 |
| Assignee | GitHub 负责人 |
| 规范影响 | 无、字体、视觉、组件、交互、多个 |
| 前后端契约 | 否、前端、后端、双端 |
| 测试状态 | 未编写、定向通过、全量通过、失败阻塞 |

## 固定视图

1. **执行看板**：按 Status 分组，显示当前工作流。
2. **当前 Release**：按 Release 筛选，按 Priority 排序。
3. **测试与发版**：筛选“待测试、待验证、失败阻塞”，显示测试状态。
4. **规范影响**：筛选规范影响不为“无”，供设计和研发共同校对。
5. **负责人负载**：按 Assignee 分组，查看待办与阻塞。

## 状态转换

`待梳理 → 待开发 → 开发中 → 待测试 → 待验证 → 已关闭`

如测试失败，退回“开发中”；如需产品决策，标记“待梳理”并在 Issue 中写明决策点。未填 Release、优先级、负责人、测试状态的 Issue 不得进入“待测试”。
