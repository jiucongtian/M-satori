# 测试与回归规范

## 用例的双层管理

- `docs/testing/<release>/`：可阅读的业务验收用例，供产品、设计和研发共用。
- `frontend/tests/`、`backend/tests/`：可执行自动化用例。

同一能力使用同一编号，例如 `R11-PAY-003`；Issue、验收文档、自动化测试和测试报告必须能相互对应。

## 执行层级

| 场景 | 必跑内容 |
| --- | --- |
| 普通修改 | 本 Issue 对应测试 + 直接关联测试 + 必要构建 |
| 前后端契约变更 | 额外运行契约测试和生成客户端校验 |
| 视觉/组件/字体变更 | 定向功能测试 + 关键页面视觉检查 |
| 测试环境部署 | 部署后关键路径冒烟测试 |
| 打 Tag / 全量回归 | 目标 Release 的前端、后端、契约、Lint、构建、自动化全量回归 |

## 当前执行入口

- R1.0：前端 `npm test`；后端 `npm test`（Vitest 全项目）。
- R1.1：`frontend/tests/r1.1/run-full-regression.mjs`；后端用例随 R1.1 服务端能力建立后加入同一门禁。

不同 Release 分支独立回归：打 R1.0 Tag 不混跑 R1.1；打 R1.1 Tag 不混跑 R1.0。
