# R1.1 权益账本与活动价上线操作手册

适用对象：负责 `fresh.shenxinyou.com` 正式环境发布、数据库迁移和切换的后端/运维同事。

## 上线目标

- 测试环境数据不进入正式环境，只发布代码与数据库结构。
- 正式环境旧智慧种子余额原数迁入批次账本，客户余额、历史记录和已有权益不丢失。
- 新账本成为唯一读写来源；旧表保留为只读历史，不长期维护双账。
- 活动价由运营后台规则决定，用户种子充足时主动选择是否使用；不足时按标准价支付。

## 上线前阻断检查

1. 备份数据库以及当前应用版本、环境文件摘要和 Nginx 配置。
2. 暂停新的应用发布，确认当前代码提交和待发布镜像一致。
3. 在只读连接上运行 `npm run db:preflight-seed-batches`。
4. 以下任意条件成立则停止上线：
   - `accounts_with_reserved > 0`；
   - `batch_internal_mismatches > 0`；
   - 数据库备份不可恢复；
   - 微信支付回调、Worker 或对账任务不健康。
5. 保存预检输出中的账户数、旧账可用总额、预留总额以及已有批次账户数，作为迁移验收基线。

预检命令只查询数据，不写入、不锁定账户，也不会生成迁移批次。

## 推荐发布顺序

1. 在低峰期短暂关闭“新建今日指引、活动价订单”入口；支付回调、查单、交付 Worker 不得关闭。
2. 执行 expand-only 数据库迁移，只新增兼容结构，禁止删除旧表和旧字段。
3. 先设置：
   - `SEED_BATCH_READ_MODE=SHADOW`
   - `DAILY_INSIGHT_CONSUMPTION_MODE=SHADOW`
4. 发布 API 与 Worker，验证旧账仍对用户提供服务，同时观察 shadow 差异日志。
5. 执行 `npm run db:migrate-seed-batches`。同一迁移版本可重复运行，但不得产生重复余额。
6. 再运行 `npm run db:preflight-seed-batches`，要求：
   - `missing_batch_accounts = 0`；
   - `batch_internal_mismatches = 0`；
   - 迁移账户数与正式环境旧账户数一致。
7. 抽查零余额、普通余额、历史消费、老注册奖励和曾购买服务的账户。
8. 同一发布窗口内同时切换：
   - `SEED_BATCH_READ_MODE=BATCH`
   - `DAILY_INSIGHT_CONSUMPTION_MODE=UNIFIED`
9. 重启 API 与 Worker，恢复新建入口。
10. 回归：登录 → MY-01 余额 → 今日指引扣 1 颗 → 抽卡权益核销 → 清和计划标准价/活动价 → 微信支付取消/成功 → 权益到账。

## 活动价验收矩阵

| 场景 | 预期 |
| --- | --- |
| 商品未配置种子活动 | 只显示和支付标准价 |
| 种子不足 | 提示当前数量和差额；不显示未获得的活动价；不消耗种子 |
| 种子充足、选择保留 | 按标准价创建订单；种子不预留 |
| 种子充足、选择使用 | 按活动价创建订单；订单创建时预留，支付成功后消费 |
| 用户取消或订单关闭 | 释放预留种子，余额恢复 |
| 支付成功 | 订单金额与报价快照一致，只消费一次种子 |

## 客户无感标准

- 老用户上线前后智慧种子可用余额一致。
- 老用户不会重新领取注册奖励；新用户按 R1.1 规则领取 3 颗。
- 历史流水仍可查询，迁移 opening grant 不重复展示为新赠送。
- 已购买会员、服务包、订单和核销记录不变化。
- MY-01 的今日指引可用次数包含智慧种子，这是规则修正，不是新增赠送。
- 页面不得出现 `NaN`、内部请求 ID、迁移状态或新旧账本术语。

## 观察与回滚边界

切换后重点观察 30 分钟，并在 24 小时内持续检查：报价失败率、订单金额不一致、种子预留未释放、支付成功未交付、账本投影差异和用户余额投诉。

- 切换到新账本前：可以回滚应用并继续读取旧账。
- 切换到新账本且已产生新消费后：禁止直接改回 `LEGACY`，否则客户可能看到旧余额“回涨”。
- 数据库只做向前兼容迁移，不执行 destructive rollback。
- 若切换后异常，先停止新的种子消费和活动价下单，保留支付回调与交付 Worker；应用可回滚到仍兼容批次账本的版本。
- 需要退回旧账读取时，必须先完成新旧流水差异回放并再次对账，不能只改环境变量。
