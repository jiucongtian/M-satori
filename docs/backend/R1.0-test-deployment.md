## 发布

服务器端 `.env.production` 不进入 Git。发布时同步代码后执行：

```bash
cd /opt/satori-test/current/backend
docker compose --env-file .env.production -f docker-compose.test.yml up -d --build --wait
```

迁移由一次性 `migrate` 服务先执行；成功后 API 和 Worker 才启动。PostgreSQL/Redis 不暴露公网端口，API 仅绑定 `127.0.0.1:3200`，由 Nginx 提供 HTTPS。

## 验证与回滚

```bash
curl -fsS http://127.0.0.1:3200/api/v1/health/ready
docker compose --env-file .env.production -f docker-compose.test.yml ps
docker compose --env-file .env.production -f docker-compose.test.yml logs --tail=200 api worker migrate
```

应用回滚使用上一 Git 提交重新构建 API/Worker。数据库迁移不得盲目降级；按 Runbook 验证 consent、Session、注销和 seed ledger 事实后再切换流量。

测试环境 `NODE_ENV=test` 使用固定验证码 `123456`。该行为禁止用于正式生产环境。
