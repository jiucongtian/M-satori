# R1.1 测试环境部署与回归说明

## 部署前

1. 测试服务器先拉取远程最新代码；若有本地改动或冲突，先完成 merge 并确认提交图没有版本回退。
2. 备份当前应用版本、环境变量摘要、Nginx 配置和数据库迁移状态。
3. 六个 `R11_*_ENABLED` 阶段开关已于 2026-09-06 移除，商业接口随版本正常开放。备份服务器环境文件后删除这六项历史变量；旧值即使保留也不再生效。支付适配器和账本迁移模式沿用当前已验收配置，不因本次升级重置。Fake 自动成功仅用于测试环境闭环验收。
4. 运行 expand-only migration；不得删除或改写订单、支付、权益、种子、会员、退款、Outbox/Inbox 事实。

## 数据迁移

1. 先以 dry-run/对账模式执行 `db:migrate-seed-batches`，保存迁移前旧账户 available/reserved 汇总。
2. 执行 opening grants 迁移；同一迁移版本重复运行必须幂等。
3. 执行 `db:reconcile-seeds`，核对新旧 available、reserved、累计流水与异常清单均为零差异。
4. 先切 `SEED_BATCH_READ_MODE=SHADOW` 观察，再切 `BATCH`；任何差异立即回到 `LEGACY`，不得反向覆盖新账本事实。

## 功能回归顺序

发布后依次验证商品与会员目录、报价、权益解析与核销、订单支付交付、会员开通续费、普通退款、会员升级。各项均由正常鉴权、参数校验和业务规则控制，无需配置版本开关。

回归同时覆盖未登录请求、非法参数和支付回调，确保移除阶段开关后安全边界仍然有效。

## 停单与兼容回滚

- 阶段开关已移除，不能再通过环境变量停单。发布异常时回滚至上一兼容版本及其配套环境文件；若需临时停单，由运维按已评审的网关规则精确限制新建订单和新支付尝试入口，不得封禁整个 API。
- 不停止支付回调、主动查单、交付 Worker、退款恢复、会员维护和对账；已支付订单必须继续到 FULFILLED 或完成异常补偿。
- API/Worker 回滚到上一个兼容提交；Nginx 恢复备份配置。数据库保持 expand 后结构，禁止对资金和账本事实做 destructive rollback。
- 微信回调网络限制只允许实际可信反向代理 IP；Test 环境确认 Docker/Nginx 真实来源地址后再配置 `WECHAT_WEBHOOK_ALLOWED_IPS`。

## 验证

- 健康检查、静态资源、认证和 R1.0 回归。
- 商城→报价→订单→Fake 支付→交付→权益查询→返回原业务上下文。
- Fake 支付不调用 `WeixinJSBridge`；真实微信未验收前保持 `PAYMENT_PROVIDER_MODE=FAKE`。
- 固定来源核销无来源切换入口；价格和优先级均不由前端计算。
- 普通退款仅处理符合快照规则的未使用普通商品；会员升级内部测算值不进入支付、退款或用户页面。
- 运行 `R1.1-commerce-operations-runbook.md` 中对账 SQL/运营视图并归档结果。
