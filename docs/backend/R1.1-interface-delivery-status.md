# R1.1 商业交易与权益接口交付状态

## 已实现

- 商品：`GET /service-offerings`、`GET /service-offerings/{id}`、`GET /membership-plans`
- 报价：`POST /checkout-quotes`
- 订单：`POST/GET /money-orders`、详情、取消、支付尝试与支付结果
- 权益：`GET /me/entitlements`、详情、`GET /me/usage-records`
- 固定核销：`POST /entitlement-resolutions`、消费意图创建/查询/开始
- 会员：当前会员、周期、升级预览、升级登记与历史
- 普通退款：`POST /refund-quotes`、`POST/GET /refunds`
- 运营：商业指标、对账 case、RBAC 修复命令和审计记录

接口边界使用公共枚举 `DAILY_ENERGY`、`COUNT`；领域内部仍使用 `DAILY_INSIGHT`、`DAILY_INSIGHT_CREDIT/READING_CREDIT`，转换只发生在 Controller。

## H5 页面

`/shop`、`/shop/detail`、`/checkout`、`/payment/result`、`/my/benefits`、`/my/orders`、`/my/membership`、`/my/refunds`、`/reading/prepare` 已完成真实 API 对接和静态构建。

## 已知限制

- 真实微信商户适配仍需测试商户凭据完成签名、主动查单、回调和金额一致性联调；未完成前只允许 `FAKE`。
- 测试服务器部署、种子真实数据迁移、逐级灰度和跨角色签字需在远程代码可用后执行。
- 会员升级按新订单全额支付；内部剩余价值只用于运营测算，不形成财务应付，也不进入用户页面。
