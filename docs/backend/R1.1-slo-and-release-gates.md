# R1.1 商业交易与权益 SLO、压测及发布门禁

## 冻结门槛

| 信号 | Test/Staging 门槛 | 止损动作 |
| --- | ---: | --- |
| 商品、报价、订单、权益查询 P95 | ≤ 100 ms（数据库/应用服务基线） | 暂停扩大灰度，检查索引、锁等待与连接池 |
| 并发权益预留 P95 | ≤ 250 ms，余额不变量 100% 成立 | 关闭新消费意图，保留查询和结算 Worker |
| 支付回调事务 P95 | ≤ 150 ms，验签/金额/币种/事件幂等全部通过 | 停止新订单，保留回调、查单、交付和补偿 |
| 1,000 条 Outbox 积压单批领取 | ≤ 2,000 ms，无重复领取 | 停止扩大支付灰度，扩容 Worker 或修复数据库 |
| 悬挂预留 | 超过 deadline 的有效预留 = 0 | 关闭新消费意图并运行消费对账 |
| 权益/种子账本 | 差异 = 0，负余额 = 0 | 关闭相关写入口，只用反向流水修复 |
| 会员周期 | 同空间 ACTIVE ≤ 1，漏发权益 = 0 | 关闭会员入口，保留周期维护与修复 Worker |

## 2026-08-29 本机 PostgreSQL 基线

环境：PostgreSQL 16 Docker、本机独立干净数据库。查询各 200 次，并发预留 100 次，支付回调事务 100 次，Outbox 积压 1,000 条。

| 信号 | 实测 P95/耗时 | 结果 |
| --- | ---: | --- |
| 商品查询 | 0.33 ms | 通过 |
| 报价查询 | 0.20 ms | 通过 |
| 订单查询 | 0.23 ms | 通过 |
| 权益查询 | 0.19 ms | 通过 |
| 并发预留 | 40.68 ms | 通过，available=100、reserved=100 |
| 支付回调事务 | 44.94 ms | 通过 |
| 1,000 条 Worker 积压领取 | 4.52 ms | 通过 |

复跑：先对独立数据库执行 expand migration，再设置 `DATABASE_URL` 运行 `npm run perf:r11`。脚本超过任一冻结门槛会以非零状态退出。

## 发布门禁

- OpenSpec strict、OpenAPI lint、类型、lint、构建、静态构建全部通过。
- 单元、契约、真实 PostgreSQL 集成和 E2E 全部通过。
- 种子 opening grants 迁移对账为零差异，`SEED_BATCH_READ_MODE` 保持可回到 `LEGACY`。
- 灰度必须严格按商品报价、已有权益核销、权益包支付、会员开通续费、普通退款、会员升级顺序开启。
- 关闭新订单后，支付回调、查单、交付、退款恢复、对账与补偿 Worker 仍保持运行。
- 真实微信商户签名、回调、主动查单和金额一致性未验证时，不得启用 `PAYMENT_PROVIDER_MODE=WECHAT_PAY`。
- 当前 Mock 测试里程碑以 `PAYMENT_PROVIDER_MODE=FAKE`、`FAKE_PAYMENT_RESULT=SUCCEEDED` 跑通服务端完整链路为 Go 条件；它不等价于真实资金验收，也不得用于生产收费。
