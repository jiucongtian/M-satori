# R1.0 SLO、压测与发布门禁

适用环境为 `test-satori.shenxinyou.com`。生产发布前必须在独立 Staging 重跑并记录同一份证据；测试环境通过不等于生产放行。

## 冻结门槛

| 信号 | R1.0 门槛 | 告警/止损 |
| --- | --- | --- |
| `GET /me`、`GET /me/home-overview` P95 | ≤ 500 ms | 连续 5 分钟超标：暂停发布并查数据库/依赖 |
| 登录（挑战 + Session）P95 | ≤ 1,000 ms（不含短信供应商） | 超标：降级发送入口并保留限流 |
| BullMQ 生成队列 | 深度 < 100、最老任务 < 120 s | 超标：限制每日指引新建、保留读取 |
| SSE | 活跃连接 < 500、终态未送达 < 1% | 断线：前端退回 Task 轮询 |
| 种子账务 | 对账差异 = 0、负余额 = 0 | 立即关闭每日指引写入口并执行对账 |

## 可重复压测

```bash
cd backend
LOAD_TEST_URL=https://test-satori.shenxinyou.com \
LOAD_TEST_PHONE=18800000000 LOAD_TEST_OTP=123456 \
LOAD_REQUESTS=40 LOAD_CONCURRENCY=8 npm run test:load-smoke
```

脚本对 bootstrap、`/me` 与 `/me/home-overview` 采样，输出 P50/P95/max；它只在一次测试登录后并发执行只读请求。生成队列、SSE 和并发账务以既有 E2E/集成测试为自动化门禁，并在 Staging 发布时用 Runbook 的队列和对账检查复核。

## Test 环境 Go/No-Go（2026-08-10）

- Go：API、Worker、PostgreSQL、Redis 健康；前端真实接口成功链路已验证；静态构建、契约、E2E、覆盖率门禁均通过。
- 实测（40 请求、并发 8）：`GET /me` P95 472 ms，`GET /me/home-overview` P95 423 ms；满足 500 ms 门槛。bootstrap P95 1,545 ms，不属于 R1 认证/首页门槛，但已列入后续性能优化观察项。
- 条件 Go：仅测试域名；每日指引确定性 Stub 继续启用；生产 Aqua、真实短信、监控告警接入后另行评审。
- No-Go 条件：账务对账出现差异、迁移/恢复无法证明事实未回滚、认证/首页 P95 超阈值、队列最老任务超阈值或任一 P0 能力 Feature Flag 被关闭。

## Feature Flag 灰度与回滚

`/api/v1/app/bootstrap` 读取 `FEATURE_LIFE_PROFILE`、`FEATURE_PROFILE_LIBRARY`、`FEATURE_WISDOM_SEEDS`、`FEATURE_DAILY_INSIGHT`。测试环境默认全部启用；逐能力灰度或止损时仅修改对应环境变量并独立滚动 API/Worker，前端按 bootstrap 重新获取状态。数据库迁移不随 Flag 回滚，账务、consent 和 audit 事实不得改写。
