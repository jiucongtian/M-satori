# Satori R1.0 后端运维 Runbook

> 适用范围：R1.0 API、Worker、PostgreSQL、Redis/BullMQ、Outbox、短信/生成供应商和智慧种子账务。所有生产操作必须记录操作者、工单、开始/结束时间、影响范围和验证结果。

## 1. 通用响应流程

1. 宣告事件级别，冻结非必要发布并保存 API/Worker 版本、迁移版本和配置版本。
2. 查看健康检查、错误率、P95、队列深度、最老任务年龄、Outbox 未发布数和账务对账结果。
3. 优先止损：关闭对应 Feature Flag、降低并发或暂停 Worker；不得直接修改账务流水和 consent/audit 事实。
4. 恢复后执行本文件对应验证，记录根因、数据影响、补偿动作和防复发事项。

## 2. PostgreSQL 故障与恢复

- 只读诊断：确认连接数、锁等待、复制延迟、磁盘和最近迁移；不得在未知范围执行 `DROP`、`TRUNCATE` 或全表更新。
- 临时止损：关闭写入类 Feature Flag，保留健康检查和只读查询；API 返回可重试错误，不转写 Redis 作为事实源。
- 恢复顺序：恢复到隔离实例 → 校验迁移表和 schema → 校验用户、consent、Session、seed ledger、Outbox 数量及外键 → 执行 `npm run db:check` → 运行完整 E2E → 切换流量。
- 时间点恢复后必须证明 consent、已撤销 Session、已完成注销和 `seed_entries` 没有被旧快照复活或改写；不满足时不得切流。

## 3. Redis/BullMQ 故障

- PostgreSQL 中的生成任务和 Outbox 是权威事实；Redis 丢失不得创建第二份业务任务或重复扣种子。
- Redis 恢复后，由 Outbox 补投未确认事件；按 `jobId=outbox.id` 去重。核对 QUEUED/RUNNING 任务与队列 job，调用现有 stale-task 恢复逻辑处理失联任务。
- 观察队列深度、最老 job 年龄、失败/重试比例；积压期间限制新生成请求，查询和历史能力保持可用。

## 4. Outbox 补投与死信

- 查询条件：`published_at IS NULL`，按 `available_at, created_at` 排序；先确认下游已恢复。
- 使用 `OutboxPublisher.publishBatch()` 小批补投并观察 attempts；不得手工复制事件或更改 aggregateId。
- generation 事件进入生成 Worker；`account.deletion.scheduled` 进入注销处理；通知型 `profile.cleanup.requested`、`account.deletion.completed` 当前由 Worker 安全忽略并保留传播事实。
- 超过重试预算的事件转入事故工单，保留原 payload、attempts 和错误；修复后以原 outbox id 补投，禁止生成新业务事实绕过去重。

## 5. SSE 降级

- SSE 失败时客户端使用 `GET /generation-tasks/{taskId}` 轮询；恢复连接携带 `Last-Event-ID`。
- PostgreSQL task event 是回放权威；Redis Pub/Sub 仅负责低延迟通知。禁止因断线重启生成任务。
- 告警关注连接数、断线率、回放延迟和终态未送达比例。

## 6. 短信与内容生成供应商故障

- 短信：保持手机号/设备/IP 限流；供应商不可用返回稳定错误，不记录验证码、手机号明文或供应商密钥。恢复后先用非生产号码验证发送与超时。
- 内容生成：R1.0 使用确定性 Stub；正式 Aqua 开关在 Staging 契约、Schema、安全内容和知识版本验收前保持关闭。
- 供应商超时不得绕过生成任务幂等、内容 Schema、安全词校验和种子 settlement。

## 7. 智慧种子账务对账与修复

- 执行：`npm run db:reconcile-seeds`。核对 account 快照与不可变 `seed_entries` 汇总、reservation 的唯一 settlement 和负余额约束。
- 不得 UPDATE/DELETE 既有流水。差异通过带审批工单和 businessKey 的 `ADJUSTMENT` 修复，并再次对账。
- 重复消费、悬挂 reservation 或退款链异常时，先关闭付费生成入口；保存相关 accountId、businessKey、resourceId 和 originalEntryId。

## 8. 密钥轮换

- 范围：Access Token、HMAC、字段加密、游标签名、短信供应商密钥。密钥仅从 Secret Manager/环境注入，不进入仓库和日志。
- 采用双读单写窗口：部署支持旧/新 key id → 新密钥写入 → 分批重加密 → 验证失败率 → 移除旧密钥。
- Access Token 轮换需定义旧 token 宽限或全量 Session 撤销；字段加密轮换必须可中断、可重放并逐批核对。

## 9. 账号注销事故

- `PENDING` 在配置的冷静期内可撤回；`PROCESSING/COMPLETED` 不可撤回。
- 执行必须撤销全部 Session、匿名化身份和反馈自由文本、逻辑删除档案，并保留 seed ledger 与 audit 事实。
- Worker 重放同一 requestId 必须幂等；失败标记 `PARTIAL_FAILURE` 并从原请求恢复，禁止创建第二个活动请求。

## 10. 发布与回滚验证清单

- `npm run typecheck && npm run lint && npm run test:contract`
- `npm run test:coverage`（需要隔离的 PostgreSQL/Redis，Statements/Lines 门禁均为 80%）
- `npm run build && npm run db:check`
- API 与 Worker 独立发布/回滚；数据库迁移只有在明确可逆且不会改写账务、consent、audit 时才允许回滚。
- 验证 bootstrap、登录、档案确认、赠种、每日指引、SSE/轮询、档案库、反馈与注销的冒烟路径。
