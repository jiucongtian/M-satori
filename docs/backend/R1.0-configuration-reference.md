# Satori R1.0 配置参考

> 适用范围：API、Worker、迁移、Seed、测试环境和生产环境。
>
> 原则：环境变量只表达部署差异、外部依赖、密钥和容量；非敏感业务、安全与可靠性规则进入版本化策略；故障注入和压测变量只属于测试工具。

## 1. 配置来源与优先级

1. `backend/docker-compose.test.yml` 为测试环境强制注入 `NODE_ENV`、`HOST`、`PORT`、`DATABASE_URL`、`REDIS_URL` 和 `COOKIE_SECURE`，优先级高于 `.env.production`。
2. 其余部署变量由服务器专用 `.env.production` 注入，完整定义、允许值和影响见 `backend/.env.example`。
3. 产品、安全和可靠性规则来自 `backend/packages/infrastructure/src/config/runtime-policy.ts`，只能通过代码评审和发版修改。
4. Stub 故障注入、数据库测试和负载测试变量见 `backend/test-environment.example`，禁止复制到生产配置。

应用启动时由 Zod Schema 校验部署变量。未知的历史变量不会改变运行策略，但发布时仍应从服务器文件移除，避免误导运维人员。

## 2. 保留的部署环境变量

| 类别 | 配置项 | 影响范围 |
| --- | --- | --- |
| 进程与网络 | `NODE_ENV`、`HOST`、`PORT` | 运行模式、监听地址和端口映射 |
| 数据基础设施 | `DATABASE_URL`、`DATABASE_POOL_MAX`、`REDIS_URL` | PostgreSQL、Redis、API 和 Worker 可用性 |
| 队列容量 | `QUEUE_PREFIX`、`QUEUE_CONCURRENCY`、`QUEUE_JOB_TIMEOUT_MS` | 环境隔离、任务并发、超时与失联恢复 |
| HTTP 与安全 | `CORS_ORIGINS`、`COOKIE_SECURE` | H5 跨域和 Refresh Cookie 传输 |
| 应用密钥 | `CURSOR_SIGNING_SECRET`、`AUTH_HMAC_SECRET`、`ACCESS_TOKEN_SECRET`、`DATA_ENCRYPTION_KEY` | 游标、身份哈希、Token 和字段解密 |
| 短信供应商 | `SMS_GATEWAY_URL`、`SMS_GATEWAY_API_KEY`、`SMS_GATEWAY_TIMEOUT_MS` | 生产验证码发送 |
| 完整每日指引 | `DAILY_INSIGHT_GENERATOR`、`AQUA_AI_BASE_URL`、`AQUA_AI_SERVICE_KEY`、`AQUA_AI_WORKFLOW_ID`、`AQUA_AI_WORKFLOW_VERSION` | Stub/Aqua 切换、Workflow 选择与回滚 |
| PROFILE-11 | `PROFILE_FIRST_LOOK_ENABLED`、`PROFILE_FIRST_LOOK_GENERATOR`、`PROFILE_FIRST_LOOK_TIMEOUT_MS` | 本地/Aqua 初识报告及超时恢复 |
| 首页摘要 | `HOME_ENERGY_SUMMARY_ENABLED`、`HOME_ENERGY_SUMMARY_TIMEOUT_MS`、`HOME_ENERGY_SUMMARY_MAX_ATTEMPTS`、`HOME_ENERGY_SUMMARY_RETRY_BACKOFF_MS` | Aqua 摘要开关、超时和重试 |
| 首页预热 | `HOME_ENERGY_PREWARM_ENABLED`、`HOME_ENERGY_PREWARM_PROFILE` | 预热开关和受控负载档位 |
| 首页 Aqua 租户 | `AQUA_BASE_URL`、`AQUA_TENANT_SERVICE_KEY` | 首页摘要的租户地址和认证 |

`backend/.env.example` 对上表每个变量都使用固定格式说明：

```text
# 用途：为什么需要该变量
# 取值：允许值、格式或范围
# 影响：修改后会影响哪些服务或业务流程
KEY=value
```

配置单测会逐项核对 Schema 变量是否具有这三类注释；漏写说明会使测试失败。

## 3. 版本化 R1 策略

| 策略路径 | 当前值 | 用途与影响 |
| --- | ---: | --- |
| `auth.accessTokenTtlSeconds` | 1800 秒 | 新签发 Access Token 的有效期 |
| `auth.refreshTokenTtlSeconds` | 2592000 秒 | 新 Session、Refresh Token 和 Cookie 的有效期 |
| `auth.otpTtlSeconds` | 300 秒 | 新验证码挑战有效期 |
| `auth.otpResendSeconds` | 60 秒 | 验证码再次发送等待时间 |
| `auth.otpMaxAttempts` | 5 次 | 单挑战最大错误尝试次数 |
| `auth.rateLimitsPerHour.phone` | 5 次 | 单手机号每小时申请验证码上限 |
| `auth.rateLimitsPerHour.device` | 10 次 | 单设备每小时申请验证码上限 |
| `auth.rateLimitsPerHour.ip` | 20 次 | 单 IP 每小时申请验证码上限 |
| `idempotency.ttlSeconds` | 604800 秒 | 登录、档案、生成、反馈和注销等写操作的幂等结果保留期 |
| `queue.maxAttempts` | 5 次 | BullMQ 与数据库生成任务的默认尝试预算 |
| `queue.backoffMs` | 2000 毫秒 | 队列和 Outbox 指数退避基础值 |
| `profile.previewTtlSeconds` | 86400 秒 | 档案预览有效期 |
| `dailyInsight.historyDays` | 90 天 | 每日指引历史查询窗口 |
| `dailyInsight.price` | 1 颗 | 每日指引预留、消费、释放、退款和接口显示的统一金额 |
| `registration.rewardAmount` | 18 颗 | 新用户创建的待领取奖励金额 |
| `accountDeletion.cancellationHours` | 168 小时 | 新注销申请的可撤销冷静期 |

修改策略时必须同步更新策略版本、单元测试、交接文档和测试环境验证记录。`dailyInsight.price` 在数据库支持价格快照前不得直接改值。

## 4. 首页预热档位

| 档位 | 天数 | 并发 | 批次间隔 | 执行周期 | 适用场景 |
| --- | ---: | ---: | ---: | ---: | --- |
| `CONSERVATIVE` | 2 | 1 | 10 秒 | 2 小时 | 外部服务不稳定、限流或成本控制期间 |
| `NORMAL` | 3 | 3 | 5 秒 | 1 小时 | 测试环境和正常运行基线 |

预热必须同时满足 `HOME_ENERGY_SUMMARY_ENABLED=true` 和 `HOME_ENERGY_PREWARM_ENABLED=true`。调整档位后需要重启 API/Worker 才会生效。

## 5. 已移除或迁移的历史变量

| 历史变量 | 处理结果 |
| --- | --- |
| `DAILY_INSIGHT_PRICE` | 移入版本化策略，并统一接入预留、消费、释放、退款和接口显示 |
| `FEATURE_LIFE_PROFILE`、`FEATURE_PROFILE_LIBRARY`、`FEATURE_WISDOM_SEEDS`、`FEATURE_DAILY_INSIGHT` | 删除；旧实现只改变 Bootstrap 响应，H5 和后端权限均未消费 |
| `QUEUE_MAX_ATTEMPTS`、`QUEUE_BACKOFF_MS` | 移入版本化队列策略 |
| `ACCESS_TOKEN_TTL_SECONDS`、`REFRESH_TOKEN_TTL_SECONDS`、`OTP_*`、`SMS_*_RATE_PER_HOUR` | 移入版本化认证策略 |
| `IDEMPOTENCY_TTL_SECONDS` | 移入版本化幂等策略 |
| `PROFILE_PREVIEW_TTL_SECONDS`、`DAILY_INSIGHT_HISTORY_DAYS` | 移入版本化业务策略 |
| `REGISTRATION_REWARD_AMOUNT`、`ACCOUNT_DELETION_CANCELLATION_HOURS` | 移入版本化产品策略 |
| `HOME_ENERGY_PREWARM_DAYS`、`HOME_ENERGY_PREWARM_CONCURRENCY`、`HOME_ENERGY_PREWARM_SPACING_MS`、`HOME_ENERGY_PREWARM_INTERVAL_MS` | 合并为 `HOME_ENERGY_PREWARM_PROFILE` |
| `DAILY_INSIGHT_STUB_MODE`、`DAILY_INSIGHT_STUB_DELAY_MS` | 移到测试专用变量，不再进入通用运行环境 Schema |
| `LOAD_TEST_*`、`RUN_DATABASE_TESTS` | 移到测试专用模板 |

## 6. 发布检查

发布前执行：

```bash
npm run typecheck
npm run lint
npm run test:contract
npm run test:unit
npm run build
```

部署测试服务器前，先备份服务器 `.env.production`，删除上表已迁移的历史键，设置 `HOME_ENERGY_PREWARM_PROFILE`，再执行 Compose。不得输出或复制任何密钥值。
