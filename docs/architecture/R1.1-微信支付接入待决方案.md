# 真实微信支付后续接入方案

更新日期：2026-08-29

## 当前范围决策

R1.1 当前里程碑使用 `PAYMENT_PROVIDER_MODE=FAKE` 跑通报价、订单、支付事实、交付、权益到账和原业务上下文恢复。测试环境允许配置 `FAKE_PAYMENT_RESULT=SUCCEEDED`，该结果由服务端 Provider 生成，H5 不拉起微信收银台，也不能自行声明支付成功。

真实微信商户接入明确后置到独立变更。下述拉起方式、凭据和资金对账输入不会阻塞当前 Mock 里程碑，但在 `WECHAT_PAY` 启用前必须全部确认并完成真实商户验收。

## 已冻结的公共边界

- 业务模块只调用 `PaymentProvider`，不读取微信证书、密钥或渠道报文。
- 支付成功只接受微信 API v3 验签并解密后的回调，或服务端主动查单结果；前端返回值不是资金事实。
- 商户请求使用商户 API 私钥和证书序列号签名；微信应答与回调必须匹配配置的微信支付公钥 ID 后验签。
- 回调使用 APIv3 密钥执行 `AEAD_AES_256_GCM` 解密，只保存事件 ID、商户订单号、微信交易号、状态等最小事实。
- 退款申请只表示渠道受理。状态为 `PROCESSING` 时继续冻结权益并由 Worker 主动查询，只有 `SUCCESS` 才追加反向权益流水并完成退款。
- 商户订单号和商户退款单号由内部 UUID 确定性压缩为 32 位，保持重试幂等。

## 后续需确认的支付拉起方式

### 方案 A：仅 JSAPI

适用于微信内置浏览器，客户端使用 `WeixinJSBridge` 调起支付。需要在支付前获得与 AppID 绑定的用户 OpenID，因此必须新增微信 OAuth 和手机号账户的身份绑定。

优点是微信内体验完整；缺点是 Safari、安卓外部浏览器不能复用同一拉起方式。

### 方案 B：仅 H5 跳转支付

适用于外部移动浏览器，服务端返回微信 H5 支付 URL，客户端跳转后回到安全白名单地址。服务端需要可信客户端 IP，不要求用户 OpenID。

优点是无需扩展账户身份；缺点是不能覆盖微信内置浏览器的完整支付体验。

### 方案 C：JSAPI + H5 双通道（推荐）

Controller 只收集已认证用户、可信客户端 IP 和服务端判定的场景；`PaymentSceneResolver` 选择 `JSAPI` 或 `H5`，再由同一 `WechatPayAdapter` 返回带判别字段的客户端参数。订单、PaymentAttempt、回调、查单、退款和对账完全复用，不把渠道差异扩散到商品、会员、权益或交付模块。

该方案覆盖微信内置浏览器和外部移动浏览器，但需要同时实现微信 OAuth/OpenID 绑定以及 H5 安全返回地址。

## 后续真实支付变更所需输入

1. 产品确认采用 A、B 或 C；默认建议 C。
2. 运维以 Secret 方式提供商户号、AppID、APIv3 密钥、商户私钥、商户证书序列号、微信支付公钥及公钥 ID、支付/退款回调域名；不得写入仓库或聊天记录。
3. 确认测试商户可使用的支付金额、测试用户、回调白名单和财务对账负责人。
