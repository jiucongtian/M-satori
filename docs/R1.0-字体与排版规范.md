# Satori R1.0 字体与排版规范

状态：已固化

适用范围：R1.0 H5 前端、测试环境与正式环境

规范版本：1.0（2026-08-21）

## 一、字体策略

R1.0 只使用随前端构建交付、授权记录可追溯的字体文件：

| 用途 | 字体 | 字重 | 授权 |
| --- | --- | --- | --- |
| 品牌、标题、疗愈表达 | Noto Serif SC | 400 / 500 / 600 | SIL Open Font License 1.1 |
| 正文、按钮、表单、数字、功能信息 | Noto Sans SC | 400 / 500 / 600 | SIL Open Font License 1.1 |

- 字体来源由 `@fontsource` 固定版本依赖锁定，并将简体中文 WOFF2 文件保存于 `frontend/public/fonts/` 随构建交付，不依赖用户设备是否安装字体。
- 字体包版本必须写入 `package-lock.json`；升级字体等同于依赖升级，必须走测试和发布 SOP。
- 授权文件随产品代码保存于 `frontend/public/fonts/licenses/`，不得删除。
- CSS 只允许使用 `--font-brand` 与 `--font-ui` 两个字体令牌；不得直接点名苹方、微软雅黑、宋体、Arial 等系统或商业字体。
- `serif`、`sans-serif` 仅作为浏览器无法加载正式字体时的兜底族名，不作为设计基准。
- 不修改字体名称、不拆改字体文件、不单独销售字体，不使用字体作者或版权方为产品背书。

## 二、字号层级

| 令牌 | 字号 | 主要用途 |
| --- | ---: | --- |
| `--type-display` | 32px | 极少量品牌展示文案 |
| `--type-hero` | 28px | 首页问候、关键情绪标题 |
| `--type-page-title` | 24px | 页面主标题 |
| `--type-section-title` | 18px | 一级内容分区 |
| `--type-card-title` | 16px | 卡片标题 |
| `--type-body-strong` | 15px | 强调正文、主要按钮 |
| `--type-body` | 14px | 正文与核心交互信息 |
| `--type-secondary` | 13px | 辅助说明 |
| `--type-caption` | 12px | 注释、次级操作 |
| `--type-label` | 10px | 英文眉题、极短标签 |

## 三、使用规则

1. 同一页面最多形成“主标题—分区标题—正文—注释”四级层次，避免字号无序增加。
2. 长篇协议与报告正文统一使用无衬线字体，字号不低于 14px，行高不低于 1.75。
3. 标题使用衬线字体时，按钮、表单、导航和数值仍使用无衬线字体。
4. 正文默认字重 400，标题 500，按钮及必须强调的信息最高 600；正文不使用 600 制造大面积压迫感。
5. 页面编号属于测试调试信息，不属于字体层级；正式构建必须关闭。
6. 新页面不得写死新的字体族；确需新增字号令牌，须先更新本规范并补充自动化测试。

## 四、验收与合规检查

- 自动化检查字体依赖、字体导入、授权文件和字体令牌均存在。
- 自动化扫描业务源码，禁止出现未经规范批准的具名字体。
- 测试构建和正式构建均应从本地静态资源加载字体，不依赖第三方字体 CDN。
- 发布前抽查首页、登录注册、档案、报告、我的、协议页，确认无字体闪动、缺字和布局溢出。
- 授权原文是合规证据的一部分；本规范为工程执行要求，不替代专业法律意见。

## 五、文件与版本

- 字体依赖：`frontend/package.json`、`frontend/package-lock.json`
- 字体文件与全局声明：`frontend/public/fonts/`、`frontend/app/globals.css`
- 字体及字号令牌：`frontend/app/globals.css`
- 授权原文：`frontend/public/fonts/licenses/`
- 自动化守卫：`frontend/tests/rendered-html.test.mjs`
