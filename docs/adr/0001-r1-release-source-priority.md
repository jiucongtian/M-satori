# ADR-0001：R1.0 版本范围与文档优先级

- 状态：Accepted
- 日期：2026-08-10
- 决策人：产品/项目负责人、后端规划

## 背景

仓库中的 R1 架构方案和 H5 API 讨论稿更新于 2026-08-09；前端交接文档更新于 2026-08-10，并基于已经冻结的 R1.0 前端实现重新定义了九项发布能力。三份文档在多人档案、智慧种子、独立人生报告、权益和部分接口范围上存在差异，必须在后端开发前确定解释顺序。

## 决策

发生冲突时按以下顺序解释：

1. `docs/研发协作与工作交接.md` 决定当前版本的产品范围、发布阻塞项和实施优先级。
2. `docs/api/H5与Satori后端接口文档.md` 决定交接文档中 `CONTRACT_DEFINED` 接口的 method、path、请求/响应结构、Cookie、错误码、幂等和分页语义。
3. `docs/architecture/R1-系统架构方案.md` 决定技术实现；被新版交接明确覆盖的产品范围变化以本 ADR 记录。

R1.0 后端据此执行以下范围：

- 必须覆盖交接文档的九项能力，包括四张关系卡牌、多人生命智慧档案库/分组和智慧种子账户/流水。
- “问事、成长、关系”实际业务仍不进入 R1.0；R1.1 抽卡问事另行变更。
- 独立人生报告列表/详情不是 R1.0 前端交接列出的发布能力，不作为本次用户功能交付；每日指引不得以 `READY` 人生报告作为前置条件，而使用已激活档案、四张卡牌及已冻结内容版本生成。
- `/me/entitlements` 和旧免费权益账本不作为 R1.0 对外结算事实；注册赠礼、每日指引及后续内容统一使用智慧种子账本。
- 通用 GenerationTask、SSE、轮询降级、Outbox、Redis/BullMQ 作为每日指引的 R1.0 基础设施实现，并为 R1.1 复用，但不提前实现卡牌领域。
- HTTP API 路径版本固定为 `/api/v1`；页面中的 R1.0/R1.1 标签不参与 API 版本命名。

## 后果

- 旧架构中“R1 不包含多人档案”被新版 R1.0 交接覆盖；实现仍沿用 Subject/LifeProfile 抽象和所有权隔离。
- 旧 API 文档中的人生报告与 `/me/entitlements` 保留为历史设计参考，若未来启用必须通过独立 OpenSpec 变更，不得隐式进入本次开发。
- 旧 API 文档中的 Session、consent、档案 preview/confirm、GenerationTask/SSE、每日指引和通用协议继续作为 `CONTRACT_DEFINED` 基线；OpenAPI 3.1 必须显式记录被本 ADR 修改的字段或前置条件。
- 注册赠礼是自动发放还是主动领取，仍需在候选契约评审中冻结，但两种策略都必须保证恰好一次入账。
