# R1.1 用户行为埋点运营平台对接说明

## 1. 当前实现状态

- 用户端已接入页面访问、关键点击、注册建档、今日指引、抽卡问事、商城订单、支付、异常与中断事件。
- 测试环境已开启采集，前端版本从 `5d40a0b` 开始包含完整事件；接收接口已验证返回 HTTP 202。
- 事件批量写入 PostgreSQL 表 `analytics_events`，以 `event_id` 去重。
- 前端每 10 条或最长约 5 秒批量发送，每批最多 20 条；服务端 5xx 或网络失败最多重试 2 次。
- 埋点失败不会阻断用户操作。
- 手机号、姓名、出生资料、用户问题、报告正文、密码、Token、Cookie、地址和 IMEI 等敏感内容禁止采集，前后端均有过滤或拦截。

## 2. 接口与开关

### 接收接口

```http
POST /api/v1/analytics/events/batch
Content-Type: application/json

{
  "events": [AnalyticsEvent]
}
```

- 成功状态：`202 Accepted`
- 单批数量：1～20
- 前端开关：`NEXT_PUBLIC_ANALYTICS_ENABLED=true`
- 环境标记：`NEXT_PUBLIC_APP_ENV=local|test|production`
- 后端开关：`ANALYTICS_INGESTION_ENABLED=true`

### 当前没有提供的接口

运营平台目前没有专用的统计查询 API。数据分析板块需要新增只读接口，由后端聚合 `analytics_events` 后返回；不要让运营平台前端直接访问数据库，也不要把全量原始事件一次性传给浏览器计算。

## 3. 数据表与公共字段

表名：`analytics_events`

| 字段 | 含义 | 运营侧用途 |
| --- | --- | --- |
| `event_id` | 事件唯一 UUID | 去重 |
| `event_name` | 事件名称 | 指标与漏斗步骤 |
| `schema_version` | 事件结构版本，当前为 1 | 兼容后续升级 |
| `occurred_at` | 客户端发生时间 | 业务统计时间 |
| `received_at` | 服务端接收时间 | 延迟和数据质量检查 |
| `environment` | local/test/production | 环境隔离，正式看板只查 production |
| `release` | 产品版本，如 R1.1 | 版本比较 |
| `app_version` | 构建版本 | 定位异常构建 |
| `commit_sha` | 前端提交号 | 发布影响分析 |
| `anonymous_id` | 浏览器匿名标识 | 匿名 UV；清缓存或换设备会变化 |
| `session_id` | 会话标识 | Session；30 分钟无活动后更新 |
| `user_id` | 登录用户 ID | 登录态由服务端校验 Session 后绑定；匿名访问为空 |
| `page_code` | 页面编号 | 页面分析与联调定位 |
| `route` | 页面路径 | 路由分析，不含查询参数 |
| `source_page` | 来源页面 | 已预留，当前并非所有事件都有值 |
| `object_type` | 业务对象类型 | offering/order/payment_attempt/reading/profile_revision 等 |
| `object_id` | 业务对象 ID | 串联商品、订单、支付或报告 |
| `result` | 结果 | success/failed/cancelled/blocked/timeout |
| `reason_code` | 原因码 | 错误与流失原因分析 |
| `request_id` | 后端请求 ID | 与服务端日志联查 |
| `entry` | 入口 | 已预留，当前并非所有事件都有值 |
| `properties` | 扩展业务字段 JSON | 用户状态、API 模板、业务结果 |
| `device` | 设备环境 JSON | 终端和视口分析 |

已有数据库索引：事件名+发生时间、用户+发生时间、会话+发生时间、接收时间。

## 7. 异常、失败与流程中断

| 事件 | 含义 | 关键字段 |
| --- | --- | --- |
| `api_request_failed` | 非埋点 API 请求失败 | `result`、`reason_code`、`request_id`、`api_template`、`http_method`、`http_status` |
| `global_client_error_occurred` | JS 未捕获异常、Promise 异常或资源加载失败 | `reason_code=UNCAUGHT_ERROR/UNHANDLED_REJECTION/RESOURCE_LOAD_FAILED` |
| `user_journey_interrupted` | 注册、今日、问事或交易流程未完成便离开页面 | `result=cancelled`、`reason_code=PAGE_HIDDEN`、`journey`、`step` |

流程类型包括：`onboarding`、`daily_guidance`、`card_reading`、`commerce`。活动流程最多在当前浏览器会话保留 24 小时。

## 9. 运营平台首批建议看板

### P0：数据健康

- 今日接收事件数、去重事件数、最近接收时间。
- 按 environment/release/app_version/commit_sha 分布。
- 客户端发生时间与服务端接收时间的延迟。
- `api_request_failed`、`global_client_error_occurred` 数量和错误率。
- 按 `reason_code`、`request_id`、页面编号、构建版本定位问题。

### P0：核心经营概览

- PV：`global_page_viewed` 数量。
- 匿名 UV：`count(distinct anonymous_id)`。
- 会话数：`count(distinct session_id)`。
- 新增注册会话：`auth_login_result_recorded`。
- 档案确认数、启程礼领取数、今日指引发起数、问事报告完成数。
- 商城访问、商品详情访问、报价、下单、支付成功数量。

### P1：四条核心漏斗

1. 注册：进入注册 → 请求验证码 → 登录/注册成功 → 同意协议 → 确认档案 → 生成初识 → 领取启程礼。
2. 今日：今日首页 → 点击今日指引 → 发起生成 → 权益来源确认 → 报告详情。
3. 问事：问事首页 → 进入问事 → 选择牌数 → 确认抽卡 → 抽卡完成 → 生成报告 → 查看报告。
4. 交易：商城 → 商品详情 → 点击购买 → 报价成功 → 订单成功 → 拉起微信支付 → 支付终态。

漏斗默认按 `session_id` 计算同一会话转化；登录用户的跨日/跨设备漏斗可按 `user_id` 计算，匿名阶段仍按 `anonymous_id` 或 `session_id` 分析。

### P1：产品与体验分析

- 各页面 PV/UV、访问路径和底部菜单点击分布。
- 各商品详情访问、购买点击、报价、下单及支付转化。
- 不同会员状态、会员计划、智慧种子余额区间的功能使用差异。
- 手机/平板/桌面、小屏/常规屏/宽屏的错误率和转化差异。
- 取消、快速重复点击、流程中断最多的页面和步骤。

## 10. 统计口径约束

1. 正式经营看板必须过滤 `environment='production'`；测试看板单独过滤 `environment='test'`。
2. 时间统一存 UTC，运营界面按 Asia/Shanghai 展示；按 `occurred_at` 归属业务日期，`received_at` 只用于数据质量。
3. UV 默认是浏览器匿名 UV，不等于注册用户数；注册用户总数应直接统计用户表，登录用户活跃数可按 `user_id` 去重。
4. 同一业务对象用 `object_type + object_id` 关联，不依赖页面文案。
5. 错误率分母需明确：页面错误率、请求错误率和业务失败率不可混用。
6. 事件是事实记录，不允许运营平台反向修改或删除；如需修正统计，应通过口径版本处理。

## 11. 运营平台开发前必须补齐的后端能力

### 必须项

1. **统计查询 API**：提供概览、趋势、漏斗、事件明细、错误排行、页面排行、商品转化等服务端聚合接口。
2. **权限控制**：数据分析接口只允许超级管理员、产品运营及获授权技术人员访问；用户级轨迹应单独授权并记录审计日志。
3. **分页与时间范围**：明细接口强制分页和最大查询区间，避免直接扫描全表。

### 已完成的用户绑定机制

- 前端只在请求头中携带当前 Access Token，不在事件体或扩展属性中写入用户身份。
- 后端允许匿名事件进入；若请求携带 Access Token，则必须验证令牌、Session 有效期、注销状态及用户状态。
- `user_id` 只取服务端验证后的身份并统一绑定到本批事件，客户端提交 `user_id` 会因严格字段校验被拒绝。
- 埋点认证失败不会阻断页面主流程；客户端后续取得或刷新有效令牌后，新事件会继续以登录身份上报。

### 建议项

- 为高频筛选增加 environment+occurred_at、page_code+occurred_at、object_type+object_id 等组合索引。
- 增加埋点数据延迟、拒收数量和异常突增告警。
- 对事件字典建立版本管理；新增或废弃事件时同步本文件和自动化测试。
