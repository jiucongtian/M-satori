# 身心游小程序登录后一次性导入

2026-09-07；适用工作分支 `release/r1.1`。本功能已实现，验证结果见文末；已部署至测试环境，尚未执行任何用户导入。

## 用户流程

1. 用户通过 Satori 手机验证码登录，完成当前协议确认；会话恢复同样检查导入状态。
2. 后端只根据已验证的 PHONE 身份跨系统匹配导入源。小程序内部先按 `userId` 连接档案与用户；历史 `userId` 已失效但 `openid` 在用户表中唯一时，使用该 `openid` 恢复内部归属，再取用户手机号匹配 Satori。存在唯一同号旧账号且有合格档案时，弹出一次性选择。
3. 提示明确说明来源为“身心游卡牌微信小程序”，档案数量、关系默认朋友、出生地默认北京，以及旧资料保留、导入后的卡牌按现行规则生成。弹窗不写死当前产品名称，方便后续更换品牌。
4. 提示文字为：“这个导入提醒只会有一次。无论选择导入或不导入，之后都不会再次提醒，也不会再有导入机会。”只有明确点击“同意导入”或“不导入，放弃此次机会”才记录决定；ESC、背景点击不能关闭。
5. 同意后全部导入为人物档案 `OTHER / FRIEND`，不创建或修改 `SELF`。保留名称与日期历法；已知时辰使用 `HOUR_RANGE`，不确定或缺标记使用 `DATE_ONLY`。默认地点北京规范 ID 为 `geonames:1816670`。
6. 在“生命智慧档案库”查看原生 Satori 档案；详情的“查看原小程序资料”保留旧名称、生日、历法闰月、原时分、性别、原四柱与原备注。修改新版本不会改动原快照。编辑未改变时间时保留原时辰精度和默认北京地点；导入档案另有出生城市搜索选择入口，保存后可改为实际出生地。
7. 拒绝后不导入，后续登录、换设备或清浏览器缓存都不再提醒。用户在正式提交选择前断网或关页面，未记录决定，下次仍需完成选择；服务器已保存同意后发生导入故障则不会再次询问。

## 决定与故障恢复

不新增表、字段、枚举或数据库迁移。沿用 `audit_logs` 保存不可变决定 `MINIAPP_IMPORT_DECIDED`，每个手机号的决定 ID 稳定且不依赖归档批次，同时按用户检查已有记录。新增 `MINIAPP_IMPORT_COMPLETED` 表示整批导入成功；档案使用原有 `subjects`、`life_profiles`、版本、卡牌绑定与原迁移标记。

同意首先提交为 `ACCEPTED`，随后另一个事务导入所有选中档案并写完成记录。中途失败时档案写入全部回滚，同意决定保留。API 每 30 秒恢复待完成的同意记录，每轮最多 20 个，游标轮转使长期失败记录不阻塞后面的用户；重启后同样读取数据库恢复。多 API 进程通过来源与用户锁串行执行。重复提交只能返回或继续原决定，不能反悔为另一个选择。离线 CLI 也拒绝绕过已保存的决定。

`ACCEPTED` 的自动恢复由运行中的 API 进程执行，不依赖用户持续打开页面；关闭 API 时保留待处理状态，启动后继续。卡牌目录或密钥故障时需运维修复，用户无需重新选择。日志仅记录固定错误类别，不记录手机号、姓名、生日或原始数据。

前端对已同意的后台任务静默观察，完成后刷新已打开的档案库；已关闭的反馈不会再次弹出。退出账号时结束观察，失焦暂停，网络错误逐步退避，不重新询问导入决定。

## 数据接入与长期保存

仍使用原 `import-miniapp.ts prepare` 生成的 AES-256-GCM 归档，无需把原始 JSON 放进数据库。将归档与密钥放入服务私有只读挂载，配置：

```dotenv
MINIAPP_IMPORT_ARCHIVE_PATH=/run/miniapp/current/source.encrypted.json
MINIAPP_IMPORT_KEY_PATH=/run/miniapp/current/archive.key
MINIAPP_IMPORT_HISTORY_PATH=/run/miniapp/history
```

前两个参数必须一起配置；不配置时不会给新用户提供导入提示，但已有决定仍生效。历史目录可选，**更换当前归档前必须保留旧批次**：

```text
/run/miniapp/history/<该批 sourceHash>/source.encrypted.json
/run/miniapp/history/<该批 sourceHash>/archive.key
```

`sourceHash` 取 `prepare` 生成的外层归档或报告，不改写；保留旧批次的归档与对应密钥，并纳入备份。它是原始资料的长期存储，不是用完可删的临时文件。不要放前端静态目录、镜像公开层、Git 或日志。归档加密密钥与 Satori `DATA_ENCRYPTION_KEY` 不同。

若整包更新但某条原始档案内容完全没变，后端按档案哈希读取相同原貌；原记录已变化时，严格从历史批次读取当时快照，不能把新记录当旧记录返回。恢复已同意导入也绑定当时归档、旧用户哈希与选定档案标记，不随手机号或新批次变化。缺失历史归档或密钥会使原资料接口返回可重试的 503，已经生成的原生 Satori 档案仍可使用；修复私有挂载后恢复。

## 适用范围

- 跨系统认领只使用服务器上的已验证手机号，客户端不能提交手机号或目标账号认领。`openid` 仅用于小程序两张源表之间恢复档案归属，不参与 Satori 账号匹配。
- 无有效手机号、同一号码对应多个旧账号、重复 `openid`、孤立档案、归属冲突和非法字段不自动导入；重复号码不直接合并，也不向用户暴露不确定归属的资料。有效但无法自动匹配的记录继续完整保存在加密归档中。
- 已删除源档案不恢复；已经成功导入且后来由用户删除的档案不重复创建。旧迁移标记与本功能共用。
- 不迁移问题、抽卡历史、解读、反馈、聊天、订单、会员、配额或管理员权限。
- 不覆盖账号本人资料、已有档案或用户后续编辑，不触发 AI 生成、付款、赠送种子或奖励。

## 接口与检查

正式契约：`backend/openapi/openapi.yaml`。所有接口均要求已登录和当前协议通过，返回统一 `{ data: ... }`。

| 接口 | 用途 |
| --- | --- |
| `GET /me/miniapp-import` | 返回 NONE、OFFERED、ACCEPTED、DECLINED 或 COMPLETED |
| `POST /me/miniapp-import/decision` | 接收 offerId 与 ACCEPT/DECLINE，要求 Idempotency-Key；持久化首次决定 |
| `GET /me/miniapp-import/profiles/:profileId` | 属主校验后读取原资料；普通档案返回 null，其他人的或已删除档案返回 404 |

运维可只读查询 `MINIAPP_IMPORT_DECIDED` 中 decision 为 ACCEPT 且没有对应 `MINIAPP_IMPORT_COMPLETED` 的用户，判断是否还有待恢复任务。不要删除决定记录来重置机会。

验证以专用本地 PostgreSQL `satori_miniapp_import_test` 和合成账号执行；浏览器测试使用正式前端并替换接口响应。真实导出代表性样本用于隔离数据库验证，实际号码和姓名不进入测试代码与报告。具体测试数量在本次交接记录中记载，不代表测试或正式环境已发布。
