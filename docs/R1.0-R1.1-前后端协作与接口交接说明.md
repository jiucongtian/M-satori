# Satori R1.0 / R1.1 前后端协作与接口交接说明

> **历史方案（2026-08-10）**：以下“无后端/候选契约/未联调”只描述当时状态。当前实现已由 [R1.1 当前交接](R1.1-current-handoff.md) 取代；可执行接口以 `backend/openapi/openapi.yaml` 为准，不得按本文重新实现一套接口。

> 面向角色：后端研发、前端研发、测试、产品  
> 更新时间：2026-08-10  
> 当前结论：R1.0、R1.1 前端交互与候选接口契约已形成；尚未完成真实后端联调，不能将“已有契约”理解为“接口已经可用”。

## 1. 文档目的

本文用于让后端研发快速了解：

1. R1.0 与 R1.1 的产品边界；
2. 对应 Git 分支、前端测试环境与版本标签；
3. 后端接口当前处于什么状态；
4. 哪些接口已在既有接口文档中定义，哪些需要后端补充；
5. 推荐的实现与联调顺序、双方交付物和验收标准。

| Git 仓库 | `jiucongtian/M-satori` | `jiucongtian/M-satori` |

| 本地测试环境 | `http://localhost:3001/` | `http://localhost:3011/` |
| 原型基准 | `http://localhost:3000/`，只作为 H5 原型基准，不是研发环境 | 同左 |
| 代码关系 | 已冻结的 R1.0 基线 | 从 R1.0 基线演进，包含 R1.0 全部能力 |

分支规则：

- `release/r1.0` 只接受 R1.0 缺陷修复，不加入 R1.1 功能；
- `release/r1.1` 承载 R1.0 全部能力和抽卡问事；
- `main` 只承载已经确认稳定的版本；
- 后端联调不得以端口判断 API 版本，HTTP API 路径统一以 `/api/v1` 开头；
- 前端页面中的 `R1.0`、`R1.1` 是产品追踪标签，不是 API 路径版本。

## 3. 状态定义

后续接口清单统一使用以下状态，避免“接口文档存在”和“接口可联调”混为一谈。

| 状态 | 含义 |
| --- | --- |
| `CONTRACT_DEFINED` | 已在《H5 与 Satori 后端接口文档》中定义，但本轮尚未验证后端部署可调用 |
| `CONTRACT_PROPOSED` | 前端已提出候选契约，待后端评审、实现并纳入 OpenAPI |
| `FRONTEND_ADAPTER_READY` | 前端已有调用适配器或 TypeScript 类型，但不代表页面已切换到真实接口 |
| `MOCK_UI` | 当前页面由前端本地状态或演示数据驱动 |
| `INTEGRATED` | 前端已经接入测试环境真实接口 |
| `VERIFIED` | 契约测试与端到端业务验证均通过 |

截至本文更新时间：整体仍处于 `CONTRACT_DEFINED / CONTRACT_PROPOSED + MOCK_UI` 阶段，尚无接口可标记为 `INTEGRATED` 或 `VERIFIED`。

## 4. R1.0 功能范围

R1.0 严格以以下九项为准：

1. 手机号登录与注册；
2. 创建本人生命智慧档案；
3. 四张关系卡牌结果；
4. 新用户智慧种子赠送；
5. 今日首页；
6. 每日指引生成与查看；
7. “我的”基本页面；
8. 生命智慧档案库基础能力；
9. 智慧种子账户及消费记录。

底部栏中的“问事、成长、关系”在 R1.0 仅展示功能预告页，不属于 R1.0 可用业务能力。

## 5. R1.1 功能范围

R1.1 包含 R1.0 全部九项，并开放“抽卡问事”完整前端流程：

- 问题输入和问题分类；
- 单卡、双卡、3—5 张多卡；
- 默认唯一卡牌体系，不提供“福禄寿喜财”等牌组选择；
- 卡牌全部由系统随机抽取，用户不能挑选具体卡牌；
- 根据抽卡张数消耗相应数量的智慧种子；
- 余额不足提示及前往获取种子；
- 抽卡、翻牌、报告生成和后台生成提示；
- 生成失败、重试和结算恢复；
- 报告详情、历史列表、反馈与分享；
- R1.1 不包含追问、提交追问和成长行动。

### 5.1 R1.1 新增候选接口

R1.1 抽卡接口未包含在现有后端接口讨论稿中。前端已建立 TypeScript 候选契约，但页面目前仍为 `MOCK_UI`。

| Method | Path | 用途 | 契约状态 | 前端适配器 | 后端关键要求 |
| --- | --- | --- | --- | --- | --- |
| `POST` | `/card-draws` | 创建一次系统随机抽卡并冻结结果 | `CONTRACT_PROPOSED` | `FRONTEND_ADAPTER_READY` | 服务端随机；结果不可由 H5 篡改；请求幂等 |
| `POST` | `/card-readings` | 基于已冻结抽卡结果创建报告任务 | `CONTRACT_PROPOSED` | `FRONTEND_ADAPTER_READY` | 校验抽卡归属；预占智慧种子；返回异步任务 |
| `GET` | `/card-readings/{readingId}` | 获取报告状态或完整报告 | `CONTRACT_PROPOSED` | `FRONTEND_ADAPTER_READY` | 只允许本人访问；返回稳定五段式内容结构 |
| `GET` | `/card-readings?cursor=...` | 获取问事历史 | `CONTRACT_PROPOSED` | `FRONTEND_ADAPTER_READY` | 游标分页；按创建时间倒序 |
| `POST` | `/card-readings/{readingId}/retry` | 重试允许重试的失败任务 | `CONTRACT_PROPOSED` | `FRONTEND_ADAPTER_READY` | 不得重复扣费；明确可重试状态 |
| `POST` | `/card-readings/{readingId}/feedback` | 提交报告反馈 | `CONTRACT_PROPOSED` | `FRONTEND_ADAPTER_READY` | 幂等或防重复；记录选项及报告版本 |

候选请求核心字段：

- 抽卡：`question`、`category`、`cardCount(1..5)`、`deckCode=RELATIONSHIP_WISDOM_DEFAULT`、`drawMethod=SYSTEM_RANDOM`、`positionLabels`；
- 生成：`drawId`、`audience=CONSUMER`、`settlement.currency=WISDOM_SEED`、`settlement.amount`；
- 反馈：`CLEARER | INSPIRED | NEEDS_TIME | NOT_HELPFUL`；
- 报告五段：`OPENING | SELF | CARDS | ACTION | CLOSING`。

后端评审时应决定：生成任务是否复用通用 `/generation-tasks/{taskId}` 与 SSE。如果复用，`POST /card-readings` 返回的 `taskId` 应完全遵循现有任务状态、错误码和重试规则，避免建立第二套任务系统。

## 6. 智慧种子统一结算要求

智慧种子是全域统一虚拟结算单位。R1.0 每日指引与 R1.1 抽卡问事都必须遵循同一账务模型：

1. 创建报告前校验可用余额；
2. 接受生成任务时预占种子；
3. 报告成功且可交付后核销；
4. 生成失败、任务取消或不可交付时释放预占或退款；
5. 同一 `Idempotency-Key` 重放不能重复扣费；
6. 账户余额与流水写入必须在同一事务边界内；
7. 流水必须记录关联业务类型和资源 ID；
8. 前端不计算最终余额，以后端响应为准。

推荐统一结算状态：`RESERVED | CONSUMED | RELEASED | REFUNDED`；流水类型：`GRANT | RESERVE | CONSUME | RELEASE | REFUND | ADJUSTMENT`。

## 7. 后端建议实施顺序

### P0：先打通 R1.0 用户主路径

1. 初始化、协议、短信登录和 Session；
2. `/me`、偏好、协议同意状态和新老用户分流；
3. 地点搜索与本人生命智慧档案预计算/确认；
4. 注册赠种、智慧种子账户与流水；
5. 首页聚合与每日指引的智慧种子结算闭环；
6. 生命智慧档案库和分组。

### P1：完成 R1.1 抽卡问事

1. 评审并冻结 `/card-draws`、`/card-readings*` OpenAPI；
2. 实现服务端随机抽卡和结果冻结；
3. 接入统一生成任务、SSE 与失败重试；
4. 接入统一智慧种子预占/核销/释放；
5. 完成历史、反馈与分享所需稳定数据；
6. 与 3011 前端环境完成主路径及异常路径联调。

## 8. 后端需交付给前端的内容

- 可导入的 OpenAPI 3.1 文档，并在 CI 中进行 breaking-change 检查；
- 测试环境 API Base URL；
- CORS、Cookie 域、HTTPS 和测试账号配置；
- 短信测试策略或固定测试验证码；
- 每个接口的真实可用状态与负责人；
- 枚举、错误码、幂等和限流规则；
- SSE 事件格式、心跳、断线重连和终态定义；
- 智慧种子测试账户及可核对的账务流水；
- AI 生成成功、失败、超时、可重试的测试触发方式；
- 数据初始化、清理和重复执行测试的方法；
- 部署版本号、Git commit、数据库迁移版本及回滚方案。

## 9. 联调验收清单

### R1.0

- 新手机号可以获取验证码、注册并建立 Session；
- 老用户登录后直接进入首页；
- 首次用户完成本人档案预计算、确认并得到四张关系卡牌；
- 注册赠种只发放一次，重复请求不重复入账；
- 每日指引成功时准确扣种，失败时余额恢复；
- 本人及他人生命智慧档案可按权限查询和维护；
- 首页、种子余额和流水最终一致；
- Token 过期、重复提交、余额不足、生成失败均有稳定错误码。

### R1.1

- 1—5 张牌均由服务端随机产生并冻结；
- 客户端不能通过修改请求指定抽卡结果；
- 抽卡结果、生成报告和当前用户正确绑定；
- 按卡数扣除对应智慧种子，重试不重复扣费；
- 报告异步状态、断线恢复、失败重试和最终交付可验证；
- 历史报告、详情、反馈和分享数据可正确读取；
- 问事报告不包含 R1.1 明确排除的追问和成长行动。

## 10. 当前阻塞项与下一步

当前前后端联调的阻塞项：

1. 尚未提供可调用的后端测试环境 Base URL；
2. `CONTRACT_PROPOSED` 接口尚未经过后端评审并进入正式 OpenAPI；
3. 前端页面尚未从本地演示状态统一切换到真实 API；
4. 尚未运行前后端契约测试、真实 E2E 和账务一致性验证。

建议下一次前后端同步会直接确认以下四项：

1. R1.0 已定义接口的真实实现进度；
2. 注册赠种、档案库、智慧种子三组候选契约；
3. R1.1 抽卡问事候选契约及是否复用通用生成任务；
4. 测试环境、联调负责人和按 P0/P1 排定的交付日期。
