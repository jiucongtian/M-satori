# Aqua 激活版本与幂等处理

2026-09-15 调用约定：所有 Aqua 工作流请求省略 workflowVersion，由 Aqua 为新幂等请求选择当前激活版本；响应 manifest 中的实际版本仍保留。首页摘要现有 workflowVersion 配置仅是旧缓存分区标识，不再发给 Aqua，避免清空已有缓存或引发批量重新生成。

- 今日指引原失败请求可按 Aqua 确认，使用原幂等键及原输入重试。省略版本不改变已绑定请求的执行版本。
- 首页摘要 IDEMPOTENCY_CONFLICT 一律停止即时重试；Redis 以 `home-energy-idempotency-conflict:<原幂等键>` 保存停止标记，后续预生成及服务重启后也跳过该键。标记无自动到期时间，避免未核对就重新发送。
- 先由 Aqua 核对旧执行及结果，确认是否可恢复既有结果。需要重新生成时必须另行授权并使用新幂等键；当前自动预生成不会自动换键。不要只删除停止标记后重试冲突旧键。
- 同一次重试必须保持原幂等键、runReference 和 input 完全一致；不要为重试刷新日期或随机生成标识。
- Redis 数据清空或丢失会失去停止标记，运维恢复时须保留它们。新键重新生成及历史任务重放不包含在本次代码修改内。
